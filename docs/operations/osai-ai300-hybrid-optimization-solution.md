# OSAI AI300 混合优化解决方案：Python 编排为主 + PyRIT 有边界升级

> **性质**：执行方案，非规范正文；与 `docs/operations/osai-ai300-curated-payloads.md` 配套使用。
> **事实源**：`docs/governance/references/OSAI-Exam-Guide-snapshot.md`（考试一手源）、`docs/governance/GOVERNANCE.md`（§2.2/§2.3/§4.5/§5.4/§6/§8.2）、`data/strategies.json` 与 `docs/operations/pyrit-integration-verification-2026-11-26.md`（策略与实测）、`docs/operations/attack-mcp-tool-verification.md`（工具面实测）。
> **边界**：演练目标非考试环境，实测命中率仅作策略间相对排序；任何结论不得写成「已确保通过」。本方案确保的是执行纪律与得分条件的可控性。

## 1. 总体架构与职责边界

### 1.1 分层与判定

编排主干为 Python 标准库实现，默认零外部依赖、延迟导入；PyRIT 仅作显式开启的能力升级，不参与判定主链。成功率的保证来自「双通道 + 边打边写 + 三态输出」三条不变式，而非载荷本身。

| 层 | 组成 | 职责 | 不做 |
|---|---|---|---|
| L0 事实层 | 考试快照、GOVERNANCE、策略库、证据片段 | 提供可追溯事实与命中率口径 | 不推断未实测结论 |
| L1 Python 编排层 | `dialogue_cli.py`、`ChatSpec`、`strategies`、`negation`、`collect_evidence.py` | 形态适配、策略选择、两次执行、双闸判定、证据落盘 | 不声明 PyRIT 已执行；不把声明当事实 |
| L2 PyRIT 边界升级层 | `--pyrit` 补位、`--semantic` 否决、`--multiturn auto` | 默认关闭；显式开启时提供多轮与评分补充；输出三态 | 不做首轮主判据；不认定攻破；不在加固目标上承诺成功 |
| L3 证据与报告层 | `loot-manage`、`verify-evidence`、`report-exam` | 战利品登记、五维校验、四章报告与提交格式 | 不补写考后证据 |

数据流：画像 → 策略选择 → L1 执行 → 双闸判定 → 证据落盘 → L3 校验与报告；失败时下探至 L2，再回流到同一证据链。

### 1.2 PyRIT 调用边界

1. **默认不调用**：首轮与常规重试一律走 L1；`pyrit_executed` 为 false 且 reason 说明未启用。
2. **显式开启**：仅在 `--pyrit` / `--semantic` / `--multiturn` 旗标下加载，缺包时给出带版本诊断，仍为 false。
3. **只否决不认定**：语义层仅在确定性命中且非否定语境后触发，返回 False 才覆盖结论；返回 True 或 None 维持原判。实测对真实泄露误否决 0/3，但认婉拒、不认「我拒绝陈述 X」，故默认关闭。
4. **多轮为最后手段**：`RedTeamingAttack` / `CrescendoAttack` / `TAPAttack` / `PromptSendingAttack` 在 1.2.1 实测可构造；对加固目标 `RedTeamingAttack` 三轮实测 `AttackOutcome.FAILURE`（92.7 秒），不得作为常规路径。
5. **事实三态**：输出必须能区分「未启用 / 启用但不可用 / 已执行且带命中数」，禁止用布尔值概括。

### 1.3 与既有编排契约的衔接

GOVERNANCE §4.5 的标准流水线保持不变：威胁建模 → 侦察枚举 → 立足点 → 链式横向与 AI 向量利用 → 独立机 → 战利品沉淀 → 域控收敛 → 证据校验 → 报告生成。`threat-model` 与 `decoy-detect` 为执行前置，`capstone-rehearse` 为考前硬门禁。本方案只优化其中的对话面执行段，不改动阶段顺序。

## 2. 端到端执行流程

### 2.1 考前准备（离线完成）

1. 固化精选清单及其分子分母、事实源路径；确认 refuted 黑名单。
2. 核对工具链：策略库可读（`--list-strategies`）、证据脚本可执行、PyRIT 1.2.1 可选状态已知、双模型凭据经环境变量注入且不落盘。
3. 准备证据模板：确切命令、关键输出、截图、脚本来源与修改说明、AI 交互四字段（提示、模型、输出、采纳）、面板值与截图值。
4. 通过 `capstone-rehearse` 门禁；未 PASS 不得进入正式考试。

### 2.2 入场时间预算

沿用 GOVERNANCE §5.4 的推荐节奏：

| 时段 | 任务 | 硬约束 |
|---|---|---|
| 0–4h | 侦察、立足点、诱饵机识别 | 不提前消耗载荷预算 |
| 4–16h | 链式推进与 AI 向量利用 | 边打边写，命中即固化 |
| 16–20h | 收敛、证据补录、报告初稿 | 报告初稿须在缓冲内完成 |
| 20–24h | ≥4h 缓冲 | 不得留到提交窗口补写 |

考试结束后另有 24 小时报告上传窗口，但证据必须在考试窗口内落盘；提交为 PDF 加无密码 `.7z`，≤100MB，命名依 OSID。

### 2.3 单目标执行循环

```text
判形态与题型 → 第一梯队 1–3 条（各 ≤2 次）→ 命中即停并固化证据
  → 失败下探第二梯队（各 1 次）→ 即时生成（带约束）→ PyRIT 多轮（最后手段）
  → 记未生效 → 下一计分单元
```

首轮执行（Python 编排，无需 PyRIT）：

```bash
python -m tools.attack_ai_agent.dialogue_cli --list-strategies
python -m tools.attack_ai_agent.dialogue_cli --target <TARGET> \
    --endpoint-template chat --strategy S-VERBATIM --strategy S-ANCHOR \
    --repeat 2 --out <EVIDENCE_DIR>/strategy-run.json
```

形态不符时只改画像，不改载荷文本；响应字段缺失时退回整段文本，不判空。

升级调用（仅在有边界的补位场景）：

```bash
python -m tools.attack_ai_agent.dialogue_cli --target <TARGET> \
    --endpoint-template chat --strategy S-VERBATIM \
    --multiturn auto --turns 3 --json
```

`--semantic` 仅在确定性命中后作为否决层显式开启；`--pyrit` 的补位结果须在对象图中如实标注。

### 2.4 证据固化与报告

命中后立即执行证据落盘，不把成功留在对话上下文中：

```bash
python tools/collect_evidence.py --step <STEP> --cmd "<确切命令>" \
    --out <FRAGMENT> --output "<关键输出>" --screenshot <SHOT> \
    --flag-panel "<面板值>" --flag-shot "<截图值>" \
    --ai-log "<提示/模型/输出/采纳>" --target <TARGET> --exam --scored-target --strict
python tools/verify_evidence.py --from-loot loot/registry.md \
    --report <REPORT> --appendix <APPENDIX> --summary
```

双通道一致性是取消资格风险的主源：面板值与截图/正文值必须一致，缺一即失分。AI 交互日志须与其它工具同等标准入报告附录。

## 3. 载荷策略与成功率管理

### 3.1 分级速查

完整载荷原文、条件与专属回退见配套文档，本方案只给分级与调度口径。

| 级别 | 条目 | 命中 | 调度 |
|---|---|---|---|
| 第一梯队 proven | S-VERBATIM、S-SYS-NOTICE、S-MEM-DUMP、S-MEM-SELFREP | 2/2 | 按题型选 1–3 条优先执行 |
| 第一梯队 proven | S-ANCHOR、S-RAG-TRIGGER | 1/2 | 凭据类与检索类首选，配合格式锚点 |
| 第二梯队 unstable | S-ROLEPLAY、S-DUAL-CLAIM、S-MEM-OVERRIDE | 1/2、0/2、0/2 | 第一梯队耗尽后限一轮 |
| 第三梯队 refuted | S-CONTEXT-PAD、S-HEADING-ASK | 0/2 | 直接跳过，不进入重试 |
| 工具面 | mcp-01、mcp-05 完全生效且高可复现；mcp-07 4/8；mcp-08 4/6；mcp-06 0/4 | 见实测 | 工具越权与取证题型按对应步骤调度 |

### 3.2 三重约束

1. **两次上限**：同一载荷最多执行 2 次；明确拒绝或触发检测规则即停，第 3 次必须换变体。
2. **双闸判定**：正则命中仅为候选，须过否定语境守卫；凭据类还须实值断言。拒绝句中的关键词一律不算命中。
3. **层级下探**：第一梯队 → 第二梯队 → 即时生成 → 多轮 → 记未生效。不得跨级直接跳到高成本路径。

### 3.3 命中率口径与退化管理

- 每条策略重复 2 次，报数一律带分子分母；`proven` 实测区间 50%–100%，读作「可复现出现」，不读作稳定成功。
- 定版实跑一致性为 8/8，3 条 unstable 不计入判定；跨轮波动已实测存在。
- 策略会退化：`S-ANCHOR` 由 2/2 变 1/2、`S-DUAL-CLAIM` 由历史成功降为 0/2、`S-ROLEPLAY` 由 refuted 改判 unstable。每次目标或模型变更后须重跑并更新状态。
- 即时生成的新载荷若经双闸确认命中，考后回填策略库；证明无效则登记 refuted，减免下次试错。

### 3.4 即时生成的边界

仅在第一、第二梯队耗尽后启用，且必须满足：带格式锚点或描述性措辞或场景化框架；主动避开 refuted 手法；生成后仍过双闸判定；AI 交互全过程入日志。

## 4. 效率与成功率的量化权衡

### 4.1 六维对照

| 维度 | 预置清单优先，失败再生成 | 完全即时生成 | 混合方案取值 |
|---|---|---|---|
| 执行耗时 | 低，可直接批量执行 | 高，每题重做分析与验证 | 主干取低耗时，补位承担必要验证 |
| 命中率 | 首轮有 50%–100% 基线 | 无基线，易落入 0% 手法 | 用基线定首轮，用补位覆盖基线外题型 |
| 试错次数 | 层级与黑名单约束 | 无约束，易重复无效手法 | 两次上限加黑名单，试错可控 |
| 认知负担 | 决策外化为清单与回退树 | 工作记忆占用高 | 清单承载决策，仅在补位时投入认知 |
| 维护成本 | 需重跑与更新命中率 | 无前期维护但重复发明 | 一次性维护，考后回填摊薄 |
| 风险可控性 | 载荷已过复核，证据模板绑定 | 措辞未验证，证据形态易漂移 | 双闸加三态加双通道，风险闭环 |

### 4.2 时间预算对齐

24 小时考试窗口内，清单优先把「分析—措辞—验证」压缩为「选择—执行—判定」，节省的时间按 §2.2 投入证据与报告初稿。多轮攻击单次实测 92.7 秒且对加固目标失败，只在该目标已无其它路径且时间预算允许时调用。≥4 小时缓冲内完成报告初稿，是应对命中率波动的时间对冲。

### 4.3 得分门槛对齐

及格线 75/100；达标最小组合之一为 4 台 AI 向量机加独立机，无需传统向量机与域控，故 AI 向量为最高杠杆。工程标准取 ≥85 以留出报告完整度折损余量。按 AI300 计分，每台 AI 向量 15 分，传统向量 10 分，域控 5 分且仅提交一次。混合方案把载荷调度集中在 AI 向量面，与传统向量面并行推进，域控按收敛路线取分。

### 4.4 混合方式带来的增量

Python 编排层承担全部确定性工作，保证可复制、可审计、零依赖可运行；PyRIT 升级层只在首轮失败后提供多轮与评分补充，并通过三态输出防止「声明即执行」的失真。两者解耦后，换目标只改画像、换打法只改策略数据、换判据只改守卫一处。

## 5. 验收与回归口径

### 5.1 门禁命令

| 检查 | 命令 | 通过口径 |
|---|---|---|
| 术语一致 | `python scripts/check_glossary.py` | PASS，废弃术语零命中 |
| 产物预算 | `python scripts/check_token_budget.py --check` | 单文件不超上限 |
| 格式 | `npx markdownlint-cli2 <文档>` | 0 issues |
| 编译 | `python scripts/check_tools_compile.py` | 退出码 0 |
| 回归 | `python -m unittest discover -s tests -t .` | 全绿，跳过数已知 |
| 策略库可读 | `python -m tools.attack_ai_agent.dialogue_cli --list-strategies` | 输出 11 条状态 |
| 证据契约 | `--strict` 落盘加 `verify-evidence` | 片段齐全、双通道一致 |

基线参考：新增 39 例全绿，全量 1636 例、2 skipped、0 失败；门禁全 PASS；定版一致性 8/8。

### 5.2 回归集与假阳性守则

回归集为 DVAA 22 条挑战。任何策略变更后须同时报「目标侧 captured」与「语义复核真实利用」两个数，后者不得下降；统计以 `completedAt` 为准，不以字段存在为准。单条通过须同时满足确定性证据（实值或遥测）与非拒绝语义，缺一记未生效。否定语境守卫回看 140 字符且不跨子句，避免拒绝污染真实泄露。

### 5.3 三态输出与边界残留

对象图须区分未启用、缺包不可用、已执行带命中数；执行事实不得由布尔字段单独表达。残留缺口：语义层拒绝识别与直觉不一致且未做多模型对比；`CrescendoAttack` 与 `TAPAttack` 仅确认可构造未实跑；本地拒绝分类器需下载模型、离线不可用；未做卸载与复装的往返实验。以上缺口不阻断方案，但须在报告中如实登记。

## 6. 风险清单与缓解措施

| 风险 | 实测或事实依据 | 缓解措施 | 门禁落点 |
|---|---|---|---|
| 假阳性误判攻破 | DVAA 22 条中 5 条系拒绝句命中关键词 | 否定语境守卫 + 实值断言；拒绝句不算命中 | 双闸判定 |
| 命中率非确定 | 同策略跨轮在 0%–100% 摆动 | 两次上限 + 分子分母报数 + 层级下探 | §3.2、§3.3 |
| 演练环境外推 | 演练目标不等于考试环境 | 先判形态与护栏，命中率只作相对排序 | §2.3、§5.2 |
| 双通道缺失或文档不足 | 官方明示可致零分 | 边打边写；面板值与截图值一致；AI 日志入附录 | §2.4、§8.2 |
| PyRIT 依赖链重 | 装包受网络与 Python 版本约束 | 延迟导入、显式开启、缺包给版本诊断 | 三态输出 |
| 时间超支 | 24h 考试 + 24h 提交窗口 | ≥4h 缓冲内完成报告初稿；多轮仅作最后手段 | §2.2、§4.2 |
| AI 使用合规 | 官方开卷且 OSEE/OSAI 并列允许 LLM | 全程记录提示、模型、输出与采纳，不照搬 AI 结论 | GOVERNANCE §5.5 |
| 明文凭据入报告 | 凭据只应产指纹 | 报告中只留指纹与形态，不落明文值 | GOVERNANCE §6.2 |

**执行判定**：本方案把考试成功率拆解为可控的得分条件——优先命中高杠杆目标、每次命中即时固化为可复现证据、所有升级路径可审计且默认关闭。实测命中率只用于排序与预算，不构成通过承诺。

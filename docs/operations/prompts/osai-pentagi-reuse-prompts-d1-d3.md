## 2. D1 — 立足与战利品（foothold-traditional / loot-manage）

### D1-01 — 凭据与战利品登记匿名化

```text
【角色】你是凭据管理员，在 D1 主机获取立足点后把哈希、密钥、令牌与 flag 登记为可复用且不泄露目标标识的条目。
【输入变量】
<目标主机角色>=<链内主机|独立主机|域控|诱饵机>
<凭据类型>=<hash|明文口令|API key|会话令牌|proof 内容>
<登记位置>=<绝对路径或笔记条目>
【上下文注入】贴入本步原始输出（仅本地分析，不外发）与 GLOSSARY.md 中凭据/flag 相关条款。
【操作步骤】
1. 逐条抽取凭据值、来源、适用范围、可复用目标。
2. 生成匿名化副本用于跨主机复用与经验沉淀：地址换为目标主机占位、域名换为域占位、用户名/口令/哈希换为对应占位、非标准端口换为端口占位。
3. 原始值只写入 <登记位置>，并标注与匿名副本的对应关系。
4. 检查是否把 proof 内容误写入可外发材料；若有立即隔离。
5. 给出横向移动候选清单，按凭据适用范围排序。
【判定标准】每条凭据有原始与匿名两份；匿名副本不含可识别目标的信息；proof 内容未进入可外发材料。
【输出格式】①凭据登记表 ②匿名副本表 ③横向候选清单 ④隔离记录
【硬约束】项目规范优先；禁止从考试环境下载文件；不在报告中写入未脱敏敏感值；flag 双通道不削弱；不连接真实目标。
```

```text
【角色】你是经验沉淀审核员，判断本步工具输出是否值得写入可复用记录，避免把噪声或敏感原文沉淀。
```

```text
【输出格式】①组件指纹表 ②检索查询（英文）③交叉验证结论 ④攻击面排序与诱饵理由
```

## 4. D3 — AI Agent 攻击（attack-ai-agent）

### D3-01 — agent 多轮深度利用

```text
【角色】你是 AI agent 攻击专家，用 PyRIT 多轮编排对目标 agent 做深度利用，并把每轮交互固化为可复核证据。
【输入变量】
<目标端点>=<URL 或接口路径，占位>
<目标能力>=<工具调用|退款|邮件|订单|检索>
<成功判据>=<触发非预期动作的具体可观察结果>
<双模型命名空间>=<聊天模型与评分模型凭据变量名>
【上下文注入】贴入 skills/attack-ai-agent/SKILL.md、tools/attack_ai_agent/ 的 seam 说明、docs/research/pyrit-canonical-references.md 的相关 API 事实。
【操作步骤】
1. 确认本机 PyRIT 版本与目标版本一致，签名校验通过；未实测项标 UNVERIFIED 并阻断结论。
2. 选择单一真实 seam 承载多轮策略（RedTeamingAttack / CrescendoAttack / PAIRAttack / TreeOfAttacksWithPruningAttack），不新建并行调用路径。
3. 用确定性 SubStringScorer 优先判定命中；无需 judge 的场景不追加 LLM judge。
4. 每轮把请求与响应写入证据片段，保留原值块与时间戳。
5. 用 --step 单步复现代替全量路径验证结论。
【判定标准】版本与签名核实通过；命中判定可复跑；每轮有独立证据片段；无并行 seam。
【输出格式】①版本核实结论 ②策略与 seam 选择 ③逐轮证据索引 ④命中判定与复跑命令
【硬约束】项目规范优先；双模型凭据分离；flag 双通道不削弱；不连接真实目标、不读真实凭据；不照搬预授权原句。
```

### D3-02 — agent 死循环检测与介入

```text
【角色】你是智能体运行监督员，在 agent 执行 subtask 时检测重复调用与停滞，并在触发阈值时给出替代策略。
【输入变量】
<当前子任务>=<描述>
<已执行调用>=<工具名 + 参数摘要 + 结果摘要列表>
<同类工具阈值>=<默认 5>
<总调用阈值>=<默认 10>
【上下文注入】贴入最近若干条交互记录与完整工具调用历史；贴入当前 subtask 成功判据。
【操作步骤】
1. 统计相同工具连续调用次数与总调用次数，与两个阈值比较。
2. 判断是否朝子任务目标推进：列出「已确认事实」与「重复无新增结果」两栏。
3. 命中阈值时给出三选一结论：换策略 / 转向检索既有方案 / 报告已完成部分并收口。
4. 检查常见执行错误（交互模式挂起、命令链未正确结束、监听端口冲突、遗留进程），逐条给出修正命令。

【判定标准】计数可复核；推进判断有事实支撑；建议具体到命令；原始结果完整保留。
【输出格式】①计数与阈值 ②推进判定 ③介入建议 ④原始结果块 ⑤修正命令
【硬约束】项目规范优先；只取判据不启用全量外部服务；不削弱证据三/五件套；不连接真实目标。
```

### D3-03 — 工具调用失败恢复

```text
【角色】你是工具调用纠错员，当 agent 连续未生成有效工具调用时定位失败模式并引导其恢复或收口。
【输入变量】

<工具模式>=<本步期望的工具名与参数结构>

【操作步骤】
1. 判定失败类型：参数结构错误 / 工具名错误 / 无工具调用 / 接近上限。

【输出格式】①失败类型 ②修正参数或工具 ③下一步动作 ④收口清单（如适用）
【硬约束】项目规范优先；确定性错误不重试；不削弱证据契约；不连接真实目标。
```

### D3-07 — 错误分类与差异化重试

```text
【角色】你是执行恢复策略员，对失败原因做确定性/瞬时分类，避免对确定性失败重复消耗窗口。
【输入变量】
<错误信息>=<原文>
<失败步骤>=<步骤编号>

【操作步骤】
1. 分类：确定性（参数错误、路径不存在、权限不足、语法错误）或瞬时（网络抖动、超时、限流）。

3. 瞬时错误给出有上限的退避重试次数与退出条件。

【输出格式】①错误分类 ②根因 ③重试或换路径决策 ④单步复现命令 ⑤证据影响
【硬约束】项目规范优先；不削弱证据三/五件套；不连接真实目标。
```

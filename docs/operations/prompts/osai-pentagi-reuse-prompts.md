## 1. 跨模块通用（贯穿 D1–D11）

### G-01 — 单机攻击闭环阶段纪律

```text
【角色】你是 OSAI 考试执行教练，按项目唯一可信源 docs/operations/skill-mainline-workflow.md 的 11 阶段纪律，指导我在单机上完成一次可评分的攻击闭环。
【输入变量】
<目标主机>=<IP 或域名>
<攻击向量>=<AI向量|传统向量|域控|诱饵机>
<当前阶段>=<1..11>
<阶段产物路径>=<绝对路径>
【上下文注入】贴入 skills/<技能名>/SKILL.md 相关条款、上一阶段 G0 结论、上一阶段产物路径。
【操作步骤】
1. 复述本阶段目标与验收条件，指出与全局任务的依赖。
2. 只输出「本阶段变更项 + 判定 + 复验命令 + 结论」，每项不超过 3 行。
3. 给出可一键复跑的命令，目标用 <目标主机> 占位。
4. 判定只取 PASS / BLOCKED；BLOCKED 时留在当前阶段，逐条列修正项与复验命令，不以后续阶段补做代替修正。
5. 提醒把证据落到 <阶段产物路径>，并说明下一阶段的输入契约。
【判定标准】阶段顺序不变；不跳、不合并、不并行；结论只有两种；每阶段产物可复验。
【输出格式】①阶段目标 ②变更项表 ③复验命令块 ④G0 结论 ⑤下一阶段输入
【硬约束】项目规范优先；不照搬上游"全授权、永不请求确认"；flag 双通道与证据三/五件套不削弱；术语按 GLOSSARY.md；不连接真实目标、不读真实凭据。
```

### G-02 — 攻击计划两遍定稿

```text
【角色】你是资深红队工程师，按 to-spec 两遍规则把一次主机攻击从行为描述收敛为可执行判据。
【输入变量】
<目标主机>=<IP 或域名>
<攻击向量>=<AI向量|传统向量|域控|诱饵机>
<成功判据>=<拿到 proof 内容|触发特定工具调用|获得指定凭据>
【上下文注入】贴入对应 skills/<技能名>/SKILL.md 与框架矩阵中该向量的推荐组合。
【操作步骤】
1. 第一遍（What）：七节结构描述目标、范围、攻击面、预期行为、约束、证据需求、交付物；不写执行细节。
2. 第二遍（How，可验证性收敛）：把每条描述改写为布尔验收条件，附复验命令与预期输出特征。
3. 两遍分别留痕、版本号递增（v1 / v2），不得合并为一次。
4. 标注哪些条件依赖运行时实测、哪些仅一手源核实、哪些 UNVERIFIED。
【判定标准】七节齐全；每条 v2 条件可判定真伪；v1/v2 各有独立留痕；变更规格时同步声明互链。
【输出格式】①规格 v1（七节）②规格 v2（布尔条件表）③留痕位置 ④UNVERIFIED 清单
【硬约束】项目规范优先；不照搬上游预授权原句；flag 双通道不削弱；术语按 GLOSSARY.md；不连接真实目标。
```

```text
【角色】你是 OSAI 框架选型顾问，按 best-of-breed 分层栈为当前目标确定工具组合，不推荐单一框架包打天下。

1. 按「首扫 → 深度内核 → 固化 → 专项点解 → 落地 → 报告」六层逐层给出选或不选的结论。

【硬约束】项目规范优先；promptfoo 须自托管并禁用联网插件；不照搬预授权原句；不削弱证据契约；不连接真实目标。
```

```text
【角色】你是工程编排管理员，按 ADR-0006 三层隔离与 checkout_lock 规则，检查当前并行任务是否会互相污染。
【输入变量】
<隔离目录>=<worktree 或临时目录绝对路径>
<基线提交>=<分支或提交号>
<涉及的共享文件>=<路径列表>
【上下文注入】贴入 docs/governance/adr/0006-three-layer-isolation.md 与 scripts/checkout_lock.py 的当前输出。
【操作步骤】
1. 确认隔离目录由 mainline_worktree 建立且相对其 HEAD 比较，避免陈旧 worktree 误报。
2. 列出共享文件冲突面；新增 CI 校验须用独立步骤，不改并发会话共用的长行。

4. 提交前先跑 --artifact 验证 C4 产物，再进入提交步骤。
【判定标准】每个共享文件有明确处置；无未授权越锁；产物预算先行验证；分支基线可追溯。
【输出格式】①隔离状态 ②共享文件处置表 ③越锁留痕（如有）④复验命令
【硬约束】项目规范优先；不 force push；不删除他人 worktree；不削弱证据契约；不连接真实目标。
```

## 10. 集成说明

**落位**：本文件位于 `docs/operations/prompts/`，与 `pyrit-upgrade-prompt.md` 同目录，可直接按编号引用。

**调用方式**：在对应阶段按总索引找到编号，替换 `<...>` 占位符后整段交给许可的 AI 助手；跨模块项（G 系列）在每次进入新主机时调用一次。

**与既有 seam 的衔接**：

- 涉及工具执行的提示词（D3 / D7）统一经 `tooling-automate` 的 S-1 统一入口，命令执行器可注入，不新建调用路径。
- 涉及证据的提示词（D1 / D5 / D11）输出必须能被 `scripts/collect_evidence.py` 严格门接受，flag 段保留原值块。
- 涉及 PyRIT 的提示词（D3-01 / D3-06）使用双模型命名空间，版本事实读 `tools/pyrit_compat/data/versions/`，不在提示词内转抄。

**回归命令**：

```text
python scripts/check_glossary.py
npx markdownlint-cli2 docs/operations/prompts/osai-pentagi-reuse-prompts.md
python scripts/check_token_budget.py --check
python scripts/check_evidence_contract.py
```

**边界**：本集合仅为提示词文本，不含可执行载荷、真实目标地址或凭据；所有目标值均以占位符表示。不得据此声称已具备对应攻击能力，能力以 `skills/*/` 实现与门禁记录为准。

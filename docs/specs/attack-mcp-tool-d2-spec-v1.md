# 规格 v1（行为）：MCP server 生命周期与端口独占

- 变更域：D-2（服务生命周期与端口独占），不覆盖 mcp-09..11 执行体
- 阶段：主线阶段 2 `to-spec` ①（What）
- 调研依据：`docs/research/mcp-server-lifecycle-winsock-posix.md`（R-1…R-8、U-1、U-2）

## 1. Problem Statement

演练用本地 MCP server 是「可启停资源」。当前行为存在三处缺陷：

1. 重复「启动」会产生第二个监听并覆盖前一个，调用方无法察觉；
2. 「关闭」只对最后一次启动生效，先前监听成为无人持有的残留；
3. 编排层对注入实例既启动又关闭，实例的归属没有约定。

在 Windows 上，同一端口还可被第二个持有者同时监听（R-1），使同一端点的请求可能落到非预期持有者；同时「端口已被占用」这一情形永远不会以错误形式暴露，导致依赖该错误的降级判断在 Windows 上是死代码，与 Linux 行为不一致（R-4）。

## 2. Solution

把「监听」当作一等资源，明确三件事：**启动幂等**、**所有权归属**、**地址独占**。

- 同一实例重复启动是无副作用的空操作；
- 一个实例在其生命周期内只有一个监听者，且只由启动方关闭；
- Windows 上端口被占用时，启动必须以可捕获的端口冲突错误失败，而不是静默共享；Linux 保持既有失败语义。

## 3. User Stories

| ID | 作为… | 我希望… |
|---|---|---|
| US-1 | 调用方 | 重复启动同一 server 不产生第二个监听、不改变端口 |
| US-2 | 调用方 | 启动前能查询 server 当前是否在监听 |
| US-3 | 编排层 | 注入一个已在监听的 server 时，不重复启动它 |
| US-4 | 编排层 | 运行结束时不会关闭不是自己启动的 server |
| US-5 | 编排层 | 自己启动的 server 在运行结束时被关闭，端口可再次使用 |
| US-6 | 演练执行者 | 端口被占用时得到明确的「端口不可用」结论，而非静默共享 |
| US-7 | 安全评审者 | 在同一端口上无法再建立第二个监听者（Windows） |
| US-8 | 测试作者 | 关闭后重绑在有限退避窗口内成功（不承诺「立即可用」） |
| US-9 | 报告读者 | 端口冲突时 mcp-02 仍判「已跳过」，理由含端口，定级语义不因修复而变 |
| US-10 | 跨平台使用者 | Linux 上端口冲突同样表现为可捕获错误 |

## 4. Implementation Decisions

- **幂等**：已监听时启动操作直接返回自身，不新建监听、不改端口、不新增工作线程。
- **可观测状态**：提供只读的「是否在监听」查询；不改动既有公开方法的签名与返回类型。
- **所有权**：谁启动谁关闭。未注入 → 编排层自建并关闭；注入未启动实例 → 编排层启动并关闭；注入已启动实例 → 编排层既不启动也不关闭。
- **地址独占**：Windows 采用独占地址选项；POSIX 不启用允许多监听者的选项。
- **地址语义不变**：未启动时的地址仍返回占位值，避免影响既有调用方；调用顺序要求写入文档。
- **错误呈现**：端口冲突以可捕获的 `OSError` 呈现，编排层既有降级分支保持不变。

**seam 结论**：沿用既有三条注入缝（传输、证据写入、截图），本变更新增 seam 数为 0；生命周期与地址策略封装在 server 内部，不向编排层泄漏新接口。（已与需求方在 D-2 方案评审时核对）

## 5. Testing Decisions

- 只断言外部可观测行为：端口号、能否建立监听、能否连接、抛出的错误类型、证据等级；不断言私有字段。
- 复用既有测试替身：假传输、记录型证据写入器、空截图。
- 新增 7 条用例（T1–T7）：幂等、同端口二次监听、注入已启动/未启动实例、端口冲突降级、关闭后重绑窗口、全量回归。
- 覆盖率沿用既有门槛（技能级 90%）。

## 6. Out of Scope

- mcp-09/10/11 的执行体与 SKILL.md 补写（D-4）。
- 监听 backlog（D-10）、读超时（D-6）、`Content-Length` 校验（D-5）。
- 鉴权、会话令牌、应用层身份区分（调研 E-3 已排除）。
- 证据片段格式、步骤契约与定级规则。

## 7. Further Notes

- 关闭后重绑只承诺「退避窗口内成功」，依据 R-3「不必然可立即复用」与 U-2。
- Linux 侧错误码与异常类型待 CI 验证（U-1），本规格不写死 `errno`。
- 若后续需要多监听者（例如并发演练共享端口），应另立规格并显式启用 `SO_REUSEPORT`，不与本规格混用。

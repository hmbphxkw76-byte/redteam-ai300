# attack-rag — 行为规格 v1（历史留痕回填）

> 回溯整理：依据 `skills/attack-rag/SKILL.md` 与既有实现、测试归纳；**不代表原流程按序执行**。
> 整理日期：2026-11-27　状态：定稿（v1）

## 1. 背景与目标

RAG 流水线把外部语料检索结果拼入模型上下文，检索层因此成为可直接操纵的信任边界。
本技能面向该边界，覆盖知识库投毒、检索相关性篡改、下游 agent 决策操纵三类攻击面。
目标是完成「定位攻击面 → 投毒 → 操纵检索 → 验证决策影响 → flag 取证」的闭环并逐步留证。
目标计分单元为 AI向量机，flag 为 `ai_vector.txt`，评分与取证要求与其余 AI 组件一致。
技术分类对齐 OWASP 关于间接提示注入与 RAG 数据投毒的条目。
本规格只描述行为与产物，不约束实现选型。

## 2. 使用者与触发场景

使用者为在授权考试或演练窗口内独立作业的红队分析人员。
触发条件为侦察已确认目标存在 RAG 流水线，且已取得可达 AI向量机的内网立足点。
RAG 流水线的判定依据包括可访问的知识库或向量库检索接口、内容摄取通道。
已确认检索入口但下游 agent 能力未明时，先枚举消费方与工具权限，再选择路径。
仅有普通 Web 或 API 目标、无检索增强特征时不适用。
检测通道（Kibana/SIEM）可用性影响判定口径，但不构成触发前提。

## 3. 输入

- 侦察产出的资产清单：向量库类型、embedding 模型、检索接口、摄取通道与暴露面。
- 已获取的身份与会话上下文：认证方式、租户或用户边界、可写入权限。
- 下游 agent 画像：是否拼接检索上下文、是否执行其中指令、是否具备工具调用能力。
- 护栏基线：检索过滤、输出审查、对检索内容的信任边界。
- 检测通道：Kibana 与相关日志索引的地址与可达性。
- 交战规则：允许的上传与注入动作范围，以及禁止项。

## 4. 输出与产物

- 每个攻击步骤的确切命令、关键输出原文与访问证明截图。
- 检索层操纵前后 top-k 对照，含投毒前与投毒后两份结果。
- 下游决策影响取证：基线决策与操纵后决策的差异及响应原文。
- 每步检测证据：触发规则名、规避盲点、规避后无新告警的确认结论。
- AI 交互日志：提示、模型、输出、采纳或修改四项。
- 上传清单：文件名、内容摘要、时间戳、目标系统、关联向量清理状态。
- flag 的双通道记录：面板提交值与同屏访问证明截图。
- 可被报告模板无损复用的证据片段集合。

## 5. 行为约束（What）

- 攻击按攻击面定位、知识库投毒、检索返回操纵、决策影响、flag 取证顺序推进。
- 每个攻击步骤必须完成枚举、朴素攻击、检测、规避、确认五环，不得只攻不检。
- 步骤以稳定标识管理，标识与可执行步骤一一对应，不得合并或缺失。
- 任何上传或注入动作前必须先确认交战规则，未确认不得上传。
- 投毒必须证明恶意内容进入目标查询的 top-k，仅写入成功不算生效。
- 检索层操纵与决策影响必须分开判定，排名变化不自动等于决策改变。
- 决策影响须以他人实体内容泄露或受害者上下文动作为硬判据。
- 效果分级必须如实，区分完全生效、部分生效、未生效与已跳过。
- 检测不可达时必须标记未确定，不得推断无告警。
- flag 取证须含身份与 flag 同屏的访问证明，双通道取值一致。
- 证据不得伪造，命令输出与截图必须来自真实执行。

## 6. 失败与豁免

- 目标 RAG 只读或无写入通道时，记录判定依据后改走间接投毒或降级，不阻塞其余路径。
- 下游 agent 与检索结果解耦时，如实记录未产生影响，不夸大，并评估改走其它向量。
- 仅检索被操纵而决策未变时，记录效果等级并注明「决策未证实」。
- 目标温度大于零导致输出不确定时，同一查询多次取证取最完整响应并记录次数。
- 读取文件使上下文超限时，改为按行分批读取，不整文件读入。
- 上传后重传改名时，如实标注混合库可能残留脏数据，不宣称已彻底清除。
- 朴素投毒触发检测规则时，不得跳过检测与规避，不重放同一被拦截载荷。
- 检测通道不可达时记录未确定并注明无法验证告警，恢复后补验。

## 7. 不在范围

- 不包含具体实现代码、框架 API 细节或文件路径。
- 不提供针对真实第三方目标的无授权利用步骤。
- 不覆盖手册中明确排除的高风险内容类型。
- 不重新定义共享证据契约或改变其字段语义。
- 不写入目标地址、凭据或 flag 明文。
- 不替代侦察技能重新枚举 RAG 资产。

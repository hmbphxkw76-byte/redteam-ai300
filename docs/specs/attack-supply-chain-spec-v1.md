## 1. Problem Statement
红队在取得内网立足点（foothold-traditional 之后、recon-ai 已确认 AI 供应链面）后，需要一个可重复、可逐步复现、证据可审计的能力，对 AI 供应链实施投毒与取证：
- 数据集 / 模型 / 适配器投毒；
- 依赖 / 包投毒（typosquat / 替换）；
- 数据管道（ETL / 预处理）投毒；
- 构建 / 运行时触发非预期代码；
- 证明下游模型行为被影响（投毒前后对照）；
- 定位并读取 `ai_vector.txt` flag（AI向量机，每台 15 分；独立机第二个 15 分）。

现状缺口：PyRIT 在供应链面无原生攻击策略（决策文档 §3.1 已核实），单一框架无法覆盖；自定义投毒脚本若无来源声明与证据契约，过不了考试报告关（文档缺失=零分）。

## 2. Solution
以 `recon-ai` 资产清单为输入，按「发现供应链面 → 数据集投毒 → 模型/适配器投毒 → 数据管道投毒 → 依赖/包投毒 → 构建/运行时触发 → 下游取证 → flag 取证」顺序推进，每步经共享证据工具产出「命令 + 输出 + 截图」三件套与「投毒前后对照 / 下游行为影响 / flag 双通道」五件套。
- 模型/适配器产物经 ModelScan 静态扫描留证（反向证明恶意载荷可被检测）；
- 投毒攻击由 IBM ART 投毒实现承载（后门 / 特征碰撞 / 梯度匹配等）；
- 全链路证据由 PyRIT `SQLiteMemory` 统一编排留痕；
- 依赖抢注、ETL 注入、构建触发三类无框架覆盖，由自定义注入脚本承载。
未过质量门不得进入下一步；每步证据可被技术读者 copy/paste 逐步复现。

## 3. User Stories（长清单）
- US-01 复用 recon-ai 资产清单，确认模型仓库、依赖源、数据管道端点与信任边界（sc-01）。
- US-02 记录正常产物哈希/来源，作为投毒效果对照基线（sc-01）。
- US-03 数据集投毒：污染训练/检索数据使模型或 RAG 产物偏向攻击者，记录脚本来源（sc-02）。
- US-04 模型/适配器投毒：植入后门权重或恶意 LoRA 适配器，记录来源（sc-03）。
- US-05 数据管道投毒：在 ETL/预处理注入恶意变换（sc-04）。
- US-06 依赖/包投毒：在镜像/包索引/requirements 注入恶意依赖（typosquat 或替换）（sc-05）。
- US-07 构建/运行时触发：使投毒在构建或推理时执行非预期代码（sc-06）。
- US-08 下游模型行为影响取证：对比投毒前后输出/检索结果，证明行为被影响，含 AI 交互日志（sc-07）。
- US-09 flag 取证：取得代码执行/数据访问后定位并读取 `ai_vector.txt`；向独立机延伸重复流程（sc-08）。
- US-10 每步产出确切命令（可直接 copy/paste）（质量门）。
- US-11 每步产出关键输出原文（投毒生效、下游偏移、触发响应）（质量门）。
- US-12 每步产出截图（访问证明，含目标标识与时间戳）（质量门）。
- US-13 产出投毒前后对照证据（产物/输出 before/after）（质量门）。
- US-14 产出下游模型行为影响证据（输出/检索差异 + AI 交互日志 §6.3）（质量门）。
- US-15 flag 双通道一致：面板提交值 == 截图/报告正文（质量门）。
- US-16 证据结构与 `report-exam` 的 Attack Walkthrough 直接兼容、可无损复用（质量门）。
- US-17 失败路径：无可用供应链面 → 记录判定改走 attack-rag/attack-embeddings（不阻塞其余）。
- US-18 失败路径：投毒部分生效 → 如实记录命中率，不夸大。
- US-19 失败路径：恶意依赖被签名/护栏拦截 → 记录拦截行为与原因，评估改走他路，不反复重试同一动作。
- US-20 失败路径：疑似诱饵机（0 分、无 AI 供应链面）→ ≤30 分钟结束，不在 0 分主机空耗。

## 4. Implementation Decisions（不含文件路径/代码片段）
- ID-01 框架分工：ModelScan 做静态扫描留证，IBM ART 做投毒/提取攻击，PyRIT 仅做证据编排（`SQLiteMemory`），自定义脚本补三者盲区。
- ID-02 证据契约：统一经共享证据工具产出三件套/五件套，保证与 `report-exam` 兼容、可由 CI 校验。
- ID-03 加载安全原则：模型文件"先扫描后加载"，优先 safetensors；加载未信文件须在隔离、无凭据环境。
- ID-04 投毒脚本来源纪律：每个示意脚本须声明来源（论文/官方示例/自研），禁止无来源实现。
- ID-05 依赖投毒采用命名空间抢注/typosquat 与 requirements 替换两类，不依赖特定包管理器。
- ID-06 扫描验证：sc-03 产出产物须经静态扫描留证，作为攻击有效性的反向证据。
- ID-07 下游取证以"投毒前后同 prompt 输出 diff + AI 交互日志"为判据，不依赖主观描述。
- ID-08 与 recon-ai / foothold-traditional 的衔接：供应链面复用 recon 资产，立足点取自传统横向之后。

## 5. Testing Decisions
- TD-01 只测外部行为（证据三/五件套齐全、命令可复现、flag 双通道一致），不断言实现细节。
- TD-02 参考测试复用既有证据契约测试夹具（与 attack-mcp-tool / recon-ai 同形）。
- TD-03 ModelScan 干净结果的非充分性：测试须显式记录"未发现问题≠可证明安全"，覆盖格式外跳过。
- TD-04 ART estimator 构造期校验：测试须覆盖误用 estimator 类型即抛错。
- TD-05 失败路径（US-17~US-20）须有判定逻辑测试，不依赖真实演练目标。

## 6. Out of Scope
- OS-01 实际考试演练目标执行（属演练，不在技能实现范围）。
- OS-02 promptfoo / garak（矩阵 ⑪ 未纳入本技能主控）。
- OS-03 传统横向 / DC 拿下（属 foothold-traditional）。
- OS-04 诱饵机识别算法（属 decoy-detect）。
- OS-05 模型文件加密/混淆对抗（超出静态扫描能力，记录于质量门）。

## 7. Further Notes
- FN-01 版本闸：ModelScan / ART 安装时以 `pip index versions` 实测回填核实文档。
- FN-02 模型文件规避：legacy 非 zip `.bin` 规避报道（2026-07）作为扫描局限记录，不阻断。
- FN-03 报告对齐：证据结构直接对接 `report-exam` 五段式，降低文档缺失零分风险。
- FN-04 计分：AI向量机 15 分/台，独立机第二个 15 分；flag 文件均为 `ai_vector.txt`。

## 8. Seam 提案（待用户核对）
- **S1 证据契约 seam**：复用共享证据工具，所有 sc-01~sc-08 经其产出三/五件套（已存在，复用）。
- **S2 投毒引擎 seam**：统一接口承载 IBM ART 投毒攻击类，sc-02/sc-03 可切换后门/特征碰撞/梯度匹配。
- **S3 模型扫描 seam**：封装 ModelScan CLI/JSON，用于 sc-03 产物静态扫描留证。
- **S4 注入器 seam**：自定义 payload 注入（依赖抢注 / ETL / 构建触发），sc-04/sc-05/sc-06 共用。
- **S5 recon 输入 seam**：消费 recon-ai 资产清单，作为 sc-01 起点。

> 共 5 个 seam（S1 复用既有，S2–S5 为新增扩展点）。位置与接口在阶段 6 收敛。

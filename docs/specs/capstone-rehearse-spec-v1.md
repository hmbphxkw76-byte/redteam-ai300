# capstone-rehearse — 行为规格 v1（七节）

> 阶段 2 `to-spec` ① · 行为唯一来源 `skills/capstone-rehearse/SKILL.md`（不改写）· 调研见 canonical 文档 · 活版本见同名 issue。

## 1. Problem Statement

§4.5 定本技能为**考前硬门禁**（未 PASS 不得进入正式考试），但无可复跑产物回答「九阶段是否就绪、证据链是否贯通、24h 是否跑得完」。人眼扫目录会：① 把「有 SKILL.md」误当就绪；② 把 §5.4 建议节奏当实测耗时；③ 把「未演练」写成「已通过」。用户需要可机读结论：覆盖度矩阵、24h 时间线、缺口与补强清单、是否具备实战条件的判定，并能被 `report-exam` 演练/附录引用。

## 2. Solution

按「全谱系走查 → 24h 节奏映射 → 缺口清单 → 演练报告」四节：

- **覆盖度矩阵**：核对 §4.5 九阶段，输出「就绪/未就绪」+「证据链贯通」；就绪 = 技能本体 + 实现落点 + 证据契约 + 片段路径合取。
- **24h 时间线**：按 §5.4 的 0–4 / 4–16 / 16–20 / ≥4h 缓冲估时，含 §5.3 ≤30min 时间盒；>24h 给压缩建议并标注超时。
- **缺口清单**：未就绪阶段 + 薄弱点逐项给补强建议，分级阻断性/非阻断。
- **演练报告**：三件产出 + 布尔判定；按路径引用片段、不重复存证据本体；与 `verify-evidence`、`report-exam` 兼容。

**隔离**：演练片段不混入正式提交；报告须标注「演练」。

## 3. User Stories

1. As 考生，I want 逐阶段核对九阶段就绪状态，so that 知道哪段未准备好。
2. As 考生，I want 就绪标记有可机读判据，so that 不把仅存在技能文件误判为就绪。
3. As 考生，I want 矩阵含证据链贯通核对，so that 上游资产清单能被下游无损消费。
4. As 考生，I want 威胁建模、侦察枚举、立足点各自判定，so that 前置缺口可定位。
5. As 考生，I want 链式 AI 利用七个子技能逐项列出，so that 任一薄弱可见。
6. As 考生，I want 独立机、战利品、域控三阶段各自判定，so that 分值与 flag 链路不漏检。
7. As 考生，I want 证据校验与报告生成作为末端单独判定，so that 提交前置顺序（§7.3）被验证。
8. As 考生，I want 未就绪阶段进入缺口清单，so that 不假称全覆盖。
9. As 考生，I want 走查带确切命令与片段路径，so that 可 copy/paste 逐步复现。
10. As 考生，I want 每阶段估算耗时，so that 能排出 24h 时间线。
11. As 考生，I want 时间线按 §5.4 分段并标关键节点，so that 知道何时收敛补录。
12. As 考生，I want 诱饵机 ≤30min 时间盒进时间线，so that 不在 0 分目标空耗。
13. As 考生，I want 累计 >24h 时给压缩/取舍建议，so that 超时有对策。
14. As 考生，I want 超时风险显式写出，so that 考前决策基于真实约束。
15. As 考生，I want 并行阶段与高杠杆目标优先的理由可见，so that 压缩方案可评审。
16. As 考生，I want 缺口清单汇总未就绪与薄弱点，so that 补强有对象。
17. As 考生，I want 每项缺口有补强建议（技能迭代/证据契约加固），so that 知道怎么补。
18. As 考生，I want 缺口分级阻断性/非阻断，so that 区分影响及格与否。
19. As 考生，I want 非阻断缺口不写成阻断，so that 不过度保守；反之亦然。
20. As 考生，I want 报告齐备矩阵、时间线、缺口清单，so that 质量门四件产出一次齐。
21. As 考生，I want 报告含「是否具备实战条件」判定，so that 硬门禁有布尔结论。
22. As 考生，I want 报告按路径引用片段、复用战利品登记簿索引习惯，so that 演练/附录可引用且不重复存证据本体。
23. As 考生，I want 报告标注演练/仿真、非 OSAI 正式考试，so that 演练片段不混入正式提交。
24. As 考生，I want 产物与 `verify-evidence` 判据兼容，so that 不与提交前校验冲突。
25. As 考生，I want 术语符合唯一术语基准，so that 规格、代码、报告不漂移。
26. As 考生，I want 「未演练」与「已通过」严格区分，so that 硬门禁结论可信。
27. As 考生，I want 实测耗时与建议值分开标注，so that 不把建议伪装为实测。
28. As 考生，I want 待取证核实闸显式列出并给取证方式，so that 结论边界清楚。
29. As 考生，I want 只做演练验收、不触发真实考试利用，so that 不污染实战环境。
30. As 考生，I want 质量门任一产出缺失即判未过，so that 四件产出不可偷减。
31. As 考生，I want 硬门禁 PASS/未 PASS 可复跑，so that 同输入得同结论。
32. As 考生，I want 每条结论附一手来源锚点，so that 判定可回溯到条款或源码。

## 4. Implementation Decisions

- **接缝（用户核对结论 2026-11-15：「2 新 + 复用 1」）**：新增「阶段就绪来源」「演练时钟」两注入点，置于走查入口最高层；证据链贯通复用既有片段解析接口。否决「3 个全新」（两套判据、违反单一事实源）与「1 个合并」（时间线与就绪扫描耦合）。
- **行为唯一来源**：保留技能原文，只翻译执行体、质量门、校验标准、失败与豁免。
- **就绪判据**：技能本体 + 实现落点 + 证据契约 + 片段路径合取；文件存在不算就绪。
- **判据单一事实源**：三件套、片段解析、登记簿索引复用既有实现，不重写判定。
- **零外部依赖**：纯标准库、确定性、离线可复跑；零 PyRIT 依赖。
- **输出模型**：版本化机读结果 + 人读报告双形态；人读按路径引用片段。
- **分级语义**：缺口用阻断性/非阻断二档；既有「判定分级」三档属提交前校验域，不复用枚举。
- **节奏事实归属**：分段耗时标「仓库建议值（§5.4，宜）」；实测须由演练取证输入，不得伪装。

## 5. Testing Decisions

- **好测试**：只断言外部行为（输入 → 矩阵 / 时间线 / 缺口清单 / 结论 / 退出码），不断言内部顺序。
- **替身边界**：两新接缝分别注入内存阶段清单与固定时钟；片段解析复用既有内存假后端。
- **夹具**：全就绪 / 缺证据契约 / 证据链断点 / >24h / 时间盒超时 / 未演练却声称通过。
- **既有参考测试**：沿用证据契约与机读校验结果测试风格，标准库 `unittest`。
- **证据契约**：每步产出「确切命令 + 关键输出 + 截图路径」；演练与正式提交片段分目录标注。
- **门禁**：全量测试通过；业务代码行覆盖率 ≥80%。

## 6. Out of Scope

- 真实考试利用、攻击考试环境、取得或提交 flag。
- 生成正式提交产物（PDF / `.7z`）、代替 `verify-evidence` 做提交前全量校验。
- 修改其它技能实现或放宽其质量门；补强建议只出清单、不代为落地。
- 自行捕获截图（沿用既有片段中的截图路径与访问证明）。
- 构造 PyRIT 对象图或调用 LLM 判定；结论由确定性判据给出。
- 把演练报告写入正式提交证据片段集合，或把演练片段混入 `-real` 目录。

## 7. Further Notes

- **优先级与门禁**：P2（§4.3.3）与 §4.5 硬门禁不冲突——能力优先级 vs 编排位置；不得判为可选跳过。
- **节奏非官方强制**：§5.4 标「宜…（非强制）」；S3 官方只给 24h 考试与提交窗口。
- **核实闸**：G-A 官方表述（外部一手源交叉验证中）、G-B 实测耗时、G-C 诱饵机时间盒、G-D 域控 `proof.txt` 双通道、G-E 正式环境不可用；取证方式见调研文档 §6。
- **隔离约束**：正式提交只接受 `-real` 真实证据片段集合；报告须写明演练标注。
- **ADR**：ADR-0002 / 0004 / 0005 / 0006 无静默冲突；不新增 ADR。

# 规格 v1（行为规格 / What）— OSAI 考试就绪优化

> 阶段 2 产物 · 行为唯一来源为官方 S3 快照与本仓库治理基线 · 本文件不写具体路径与代码

## 1. Problem Statement

仓库已具备覆盖 AI 向量与传统向量的技能、证据收集器、报告组装器与十项机读校验，但存在四类会导致考试失分的行为缺口：

1. 截图钩子命令被当作真实截图，片段可以显示「三件套齐全」而实际没有截图文件；这是官方取消资格条款的直接触发面。
2. 没有把八个计分目标映射成可核查的单一事实源， flag、截图、报告小节的完成状态散落在片段与登记簿中。
3. 编排层只做被动校验，不推进阶段；演练层只校验不修复，无法证明 recon→攻击→战利品→证据→报告首尾衔接。
4. 报告骨架存在默认占位文本，提交件命名、体积与 MD5 校验未形成可复跑门禁。

## 2. Solution

在保留现有演练语义的前提下引入**考试模式**：考试模式下，截图必需件必须由真实图片文件满足，钩子命令只能记为待补录；建立八目标映射作为唯一事实源；把既有交接校验升级为显式阶段状态机；把报告与提交物收口为可复跑的预检门禁。所有产物均标明演练或正式，不虚构考试事实。

## 3. User Stories

- 作为考生，我要在生成每步证据时明确区分「真实截图已落盘」「仅有钩子待补录」「截图缺失」，避免误判导致失分。
- 作为考生，我要看到任一计分目标的证据完整度，包括命令、输出、截图、flag 双通道与报告引用。
- 作为考生，我要在考试窗口内按固定顺序推进阶段，并在交接失败时停留而不是静默跳过。
- 作为考生，我要在提交前自动发现报告中的占位文本、断图与缺失引用。
- 作为考生，我要按官方规则校验 PDF 与压缩包命名、无密码、体积上限，并计算本地 MD5 供上传后比对。
- 作为审计者，我要从目标映射表一键定位每个目标对应的证据片段、flag 登记与报告小节。
- 作为维护者，我要在不改动既有演练片段契约与消费者解析的前提下引入考试模式。
- 作为维护者，我要用独立校验脚本发现未走完整主线的技能与孤儿规格，而不改动并发共享长行。
- 作为考生，我要在不依赖联网与外部服务的前提下完成全部本地门禁。
- 作为考生，我要明确知道哪些事实仍待考试窗口取证，绝不被演练数据伪装成正式提交件。
- 作为评审者，我要看到每项改动对应的需求、动作、验证命令、预期结果与实际状态。

## 4. Implementation Decisions

- 采用单一开关区分演练与考试，默认行为保持兼容；考试语义只在显式开启时生效。
- 截图状态继续沿用既有三态字段，不新增第四态；考试模式下「待补录」不得计入完成。
- 目标映射采用单一事实源，其他位置只写指针，不复制片段内容。
- 阶段状态机复用既有交接校验作为判据，不另立平行校验逻辑。
- 报告预检与提交校验采用独立入口，不侵入现有生成器骨架的章节结构。
- seam 提案：沿用证据收集器的唯一 CLI 边界与既有交接校验边界，不增加外部依赖；核对结论为沿用（用户已确认在现有实现上直接落地）。

## 5. Testing Decisions

- 用标准库单测覆盖：钩子-only 在考试模式下未完成、真实截图在考试模式下完成、既有演练模式行为不变。
- 用 golden 片段回归下游解析，确保节标题与 flag 原值块不变。
- 用临时目录构造正/负目标映射与报告样例，验证门禁的布尔判定。
- 用全量测试与覆盖率确认未破坏既有 17 技能测试。
- 不测试实现细节，只断言外部可观察行为与退出码。

## 6. Out of Scope

- 不连接真实考试环境，不获取或伪造 flag、截图、OSID。
- 不生成正式提交件；所有产物标记为演练。
- 不修改既有 17 份技能的行为描述，不重写官方报告模板。
- 不引入第三方运行时依赖，不联网调用评分或生成服务。
- 不修改 CI 工作流并发长行；新增校验为独立步骤。

## 7. Further Notes

- 本规格与阶段 1 事实基线互链；待核实项保持开放，直到考试窗口取证。
- 优先级以考试得分杠杆排序：证据/报告关 > AI 向量 > 传统/DC。
- 术语沿用既有基准；本轮不新增术语条目。

# osai-handoff-gateway 行为规格 v1（What）

> 行为唯一来源：`docs/research/osai-skill-handoff-design.md`（阶段 1 G0 PASS）。
> 上游模块：`skills/osai-exam-orchestrator/SKILL.md`（已合入 `ae3cbe4`）。
> 本版本只回答「做什么」，不含文件路径与代码。

## 1. Problem Statement

OSAI（AI-300）考试的通过率由报告完整性决定，而六段交接中存在已核实的真实缺陷：证据→报告阶段静默丢弃侦察片段、报告→提交阶段断图不阻断、战利品双通道把截图路径当成 flag 值导致自比假阳性。这些问题独立于攻击成败，直接造成失分。需要一个不改变任何既有 skill 语义的旁路能力，在每段交接处给出可机读的一致性判定。

## 2. Solution

以 `step_id` 为贯穿六段交接的唯一关联键，从既有产物派生交接索引（不新增权威存储），在每段边界执行一致性校验并输出与 G0 同语义的 PASS / BLOCKED。校验不替代人工确认，不放行攻击动作，只判定数据是否可安全传递。

## 3. User Stories

- US-1 作为考生，我能在进入攻击前确认资产清单可解析且存在性三态齐全，避免把未判定项当成资产。
- US-2 作为考生，我能在落证据后确认计分步骤有真实截图文件，避免截图钩子制造假阳性。
- US-3 作为考生，我能确认 flag 登记行的面板值与截图路径是两个独立字段，避免自比。
- US-4 作为考生，我能在横向移动前查询可复用凭据，避免重复爆破且失效项不被复用。
- US-5 作为考生，我能确认侦察片段按主机进入报告枚举段，避免缺文档扣分。
- US-6 作为考生，我能在提交前确认断图检查已执行、时间锚已落盘、加密问题不命中，避免提交被拒。
- US-7 作为考生，我能用一条命令得到六段交接的逐段判定与复验命令，无需手工翻查多份产物。
- US-8 作为工程使用者，我能验证实现逐条对齐候选 A 设计，无偏离。

## 4. Implementation Decisions

- 新增能力域挂靠已合入的编排增强层，不改既有 skill/tool 实现。
- 判定结果复用既有 `GateResult` 值类型（PASS / BLOCKED），与主线 G0 同语义。
- 三份契约均为既有事实源的路径指针，不复制正文，符合 C1。
- 派生索引随用随生成，不落盘为新的权威数据源。

## 5. Testing Decisions

- 只测外部行为：输入既有产物路径，断言判定值与理由，不断言内部实现。
- 每段交接至少一条失败用例与一条通过用例。
- 对齐矩阵断言设计文档中每条核心条款都有实现锚点。

## 6. Out of Scope

- 不实现攻击逻辑、不连接真实目标、不读凭据、不投放载荷。
- 不修改 `collect_evidence.py`、`report_exam`、`verify_evidence` 的既有语义。
- 不自动提交 flag、不放行阶段门禁。

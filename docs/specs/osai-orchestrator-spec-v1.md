# osai-orchestrator 行为规格 v1（What）

> 回溯整理：依据 `skills/osai-orchestrator/SKILL.md` 与既有实现、测试归纳；**不代表原流程按序执行**。
> 整理日期：2026-11-27　状态：定稿（v1）

## 1 背景与目标

OSAI（AI-300）考试窗口长、攻击链长，失分主因常不是攻击失败，而是运行期失控：同工具重复调用卡死、连续失败后继续跑飞、上下文膨胀挤掉证据路径、关键步骤无人复核、报告模板缺变量仍被提交。既有攻击技能各自实现攻击逻辑，没有共享的韧性层，逐技能改造的破坏面不可接受。

目标：把 PentAGI 迁移清单 A/B 类判据实现为**纯增量**运行时能力层，只增强既有技能，不改写任何既有 `SKILL.md`、`tools/*` 文件与 `GLOSSARY.md` 条目语义；零第三方依赖、零 PyRIT 运行时强依赖。

命名事实（2026-11-27 已统一）：技能目录 `skills/osai-orchestrator/`、覆盖率目标 `osai-orchestrator` 与 Python 包名 `tools/osai_orchestrator/`（下划线为 Python 命名规范）指向同一能力域。历史文档中的旧称保留在版本历史中，不作为当前标识使用。

## 2 使用者与触发场景

- 考生：在 24 小时窗口内需要「防卡死、防跑飞、压缩上下文、人在环确认、独立复核」，但不希望改变任何攻击技能的用法。
- 审计者：需要从报告与证据片段独立复核结论，不依赖执行者自述。
- 维护者：需要以可注入依赖、可单测的模块方式扩展编排能力，避免散改各既有攻击技能。

触发场景：单次任务的工具调用次数或同工具重复次数接近阈值；连续失败达到三振；待办步骤超出角色预算；目标达成但证据不全；上下文需压缩；交接边界需判定数据是否可安全传递。

## 3 输入

- 设计输入：迁移清单 A/B 类判据、4 份考试提示词分册、既有 S-1 入口（`tooling-automate`）、`tools/pyrit_compat/` 版本注册表。
- 运行输入：任务步骤清单、工具调用序列（工具名/是否推进）、失败计数与恢复动作、工具调用配额、证据片段与截图状态、flag 登记表、报告草稿或模板变量表。
- 约束输入：`GLOSSARY.md` 术语、证据契约与 flag 双通道语义、GOVERNANCE §6/§8.2。

本模块不接收目标地址、凭据或载荷作为能力输入；外部命令仅经可注入的执行器抽象。

## 4 输出与产物

- 运行时判定值：监控/反思/配额/栅栏结论、计划与精化结果、压缩后上下文、匿名化文本、复核条目、工具准入与重试决定、模板渲染结果、本体校验结论。
- 交接与网关判定：六段交接的逐段结论（PASS/BLOCKED）与理由、D11 一致性网关结果、考试阶段流水线的当前阶段与是否可推进。
- 交付形态：`tools/osai_orchestrator/` 模块包，覆盖 19 项能力域；CLI 的 `--plan`（列出能力域，无副作用）与 `--anonymize`（返回占位符化文本）；能力域清单与阶段门禁记录。

所有判定为纯数据输出，不写外部状态、不发送网络请求。

## 5 行为约束

- 运行时监督：同工具默认 5 次、总调用默认 10 次触发提示；是否推进由调用方给事实，模块不猜测；连续失败默认 3 次给出继续/终止判定，无恢复动作即收口；工具配额按角色硬上限（通用 100 / 受限 20），超限判 `BLOCKED` 并要求重排；栅栏仅在目标达成、证据路径存在、flag 双通道核验通过时放行 `done`，否则 `ask`。
- 计划与人在环：计划 3–7 步，`step_id` 唯一且含验证点；精化仅支持增/删/改/重排，已完成步骤不可变；人环控制状态先于变更、一次一动作。
- 上下文与记忆：摘要标记为历史上下文；检索片段中的指令式内容只标记不执行；压缩保留 IP、证据路径与步骤标识且不产生新建议；匿名化替换地址/域名/凭据/令牌；记忆白名单只收方法论。
- 工具治理：按类型与角色限定工具集；调用 ID 归一化并修复残缺参数；确定性错误零重试；检索仅接受本地来源、无目标标识的命中，默认上限 5。
- 报告治理：模板缺变量即 `BLOCKED`；本体节点/关系/状态词表固定，禁止自造。
- 工程约束：不修改既有技能与既有工具文件；不复述证据正文，只引路径；术语以 `GLOSSARY.md` 为准。

## 6 失败与豁免

- 本模块不含攻击逻辑，不连接真实目标、不读凭据、不投放载荷；失败时返回判定与理由，不静默降级。
- 未实现的 A/B 项如实列入缺口，不伪造能力；C 类判据不实现。
- 与既有技能语义冲突时以既有技能为准，本模块只提供可选增强，调用方可不用。
- 证据三/五件套、flag 双通道、11 阶段顺序与 to-spec 两遍均不因本模块改写；本模块不构成豁免依据。

## 7 不在范围

- 不实现 C 类项：新语言栈服务、图数据库、可观测栈、容器守护进程、多 provider、前端、镜像选择、BAS 剧本。
- 不替代或重写任何既有攻击技能、证据收集器、报告组装器；不新增权威存储。
- 不自动判定攻击是否推进，不引入 LLM judge，不改变报告章节结构。
- 不承诺压缩后的语义等价性，只保证指定标识与路径不丢失。

层次关系：本规格是技能级全量行为规格；`docs/specs/osai-exam-readiness-spec-v{1,2}.md` 与 `docs/specs/osai-handoff-gateway-spec-v{1,2}.md` 属就绪度与交接网关的变更域规格，晚于本技能落地，仅作补充证据引用，不替代本规格。

# report-exam — 行为规格 v1（历史留痕回填）

> 回溯整理：依据 `skills/report-exam/SKILL.md` 与既有实现、测试归纳；**不代表原流程按序执行**。
> 整理日期：2026-11-27　状态：定稿（v1）

## 1. 背景与目标

考试报告是 OSAI 认证的计分交付物，须与 OffSec 官方模板（S1）逐节对齐。证据散落于各技能 `collect_evidence.py` 片段、`evidence/` 目录与 loot 登记簿，人工拼装存在漏节、改写命令、遗漏双通道与命名不合规等失分风险。
本技能把既有证据管线无损复用为对齐 S1 的 EN 官方版报告与 ZH 内部镜像，并完成 PDF 与无密码 `.7z` 打包，供 `verify-evidence` 提交前校验。
目标是使报告结构、证据逐字性、双版事实一致与提交命名可被机读校验，降低 24h 提交窗口内的人工差错。
本规格只描述行为与产物，不约束具体实现与框架选型。

## 2. 使用者与触发场景

使用者为完成取证、进入报告撰写窗口的红队分析人员。
触发条件为各攻击技能取证完成、`loot-manage` 登记簿就绪、`verify-evidence` 提交前校验通过。
也适用于仅有 `evidence/` 目录、尚无 loot 登记簿的演练态，此时以证据片段路径自建主机映射。
不适用于重新取证或向目标发起攻击，本技能只消费既有证据。

## 3. 输入

- `loot-manage` 战利品登记簿 `loot/registry.md`，列含编号、类型、内容、来源主机、证据片段路径、时间戳、状态、双通道。
- 各技能 `collect_evidence.py` 证据片段 `evidence/<skill>-real/*.md`。
- `verify-evidence` 校验结论，含通过、阻断与缺失项清单。
- AI 交互日志与截图访问证明。
- 控制面板 flag 提交值，用于双通道逐字比对。
- 考试元信息：OSID、邮箱与提交命名所需字段。

## 4. 输出与产物

- 对齐 S1 的四章报告：Introduction/Objective/Requirements、Executive Summary、Attack Walkthrough、Appendix。
- 每台计分主机的五段式小节：枚举、漏洞描述与完整利用、提权、flag 取证、证据归属。
- EN 官方版（提交候选）与 ZH 内部镜像两版 markdown，事实逐字一致。
- AI 会话历史附录 D 与长 PoC 附录 A。
- `OSAI-OS-XXXXX-Exam-Report.pdf` 与同名无密码 `.7z`（≤100MB）。
- 机读校验结果：八项检查、AC 判定与提交就绪结论。

## 5. 行为约束

- 证据片段必须逐字 include，命令、输出、截图与源片段零差异，禁止转写或润色。
- 每台计分主机必须独占一节，不得多主机合并。
- 域控在 Chain 1 与 Chain 2 两处均须记录，`proof.txt` 仅提交一次。
- 2 台诱饵机须记为「确认不可利用」并有枚举佐证，不计分但须入报告。
- EN 与 ZH 两版证据标识、flag、命令、输出、IPv4 与时间戳必须逐字一致。
- 每段引用必须标注来源证据片段路径，可回溯至原子证据单元。
- AI 生成内容入正文前必须经人工校验并标注「经人工校验采纳」。
- 术语必须符合 `GLOSSARY.md`，使用攻击链、独立主机、域控、AI向量机、传统向量机、诱饵机，禁用废弃术语。
- 未达成目标须如实记「未达成 + 已推进程度」，不得虚构利用过程。

## 6. 失败与豁免

- 某计分目标未取分时，对应小节记「未达成」及已推进程度，不虚构。
- 正文长度失控时，长 PoC 与补充截图分流附录，正文保留最小可复现链路。
- 截图缺失时回溯对应技能按证据契约补录，禁止以文字替代访问证明截图。
- 提交窗口临近时，优先清零双通道一致、四章齐全、命名合规与 `proof.txt` 单次四项阻断项，剩余非阻断瑕疵记录在案。
- 宿主环境缺 pandoc 或 7z 时，打包转核实闸并显式失败，不静默跳过。

## 7. 不在范围

- 不重新取证，不调用任何攻击逻辑，不涉及 PyRIT 对象图。
- 不移植失败项目 `offsec-report` 的 `report_data.json` 等旧流水线。
- 不把演练或仿真证据混入正式提交。
- 不臆造未核实数值，窗口、体积与评分细则待官方源复核。
- 不写入目标地址、凭据或 flag 明文。
- 不提供具体实现代码、框架 API 细节或文件路径。

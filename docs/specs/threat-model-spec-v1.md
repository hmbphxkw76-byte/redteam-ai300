# threat-model 行为规格 v1

> 回溯整理：依据 `skills/threat-model/SKILL.md` 与既有实现、测试归纳；**不代表原流程按序执行**。
> 整理日期：2026-11-27　状态：定稿（v1）

## 1. 背景与目标

`threat-model`（D10/P1，通用·前置）在考前 24h 规划窗口（§5.4）把 `recon-ai` 资产清单转化为优先级攻击图，先打最高杠杆目标、避开 0 分诱饵机（§5.3），其输出是 §4.5 编排流水线的入口驱动。目标：用可机读、可复现的规划结论替代临场猜测——资产排序、信任边界、最短攻击路径、诱饵排除、编排顺序五类结论必须成套产出。技能仅做规划，不含任何实际攻击利用；结论由对应攻击子技能在实战中验证。

## 2. 使用者与触发场景

使用者为红队分析师/编排者。触发场景：① `recon-ai` 资产清单就绪且进入规划窗口；② 分析师提供假设、检测规则、信任边界或 RoE 约束时做 Ch10 增量建模；③ 按新情报对既有威胁模型增量重建（保留决策日志与已验证假设）；④ 需把 AI 身份链（IAM/K8s）投影进资产/边界/路径（Ch9）。

## 3. 输入

- recon 资产清单（七字段：assetID/类别/产品引擎/版本/暴露端点/凭证指纹/关联证据 step_id），只读消费。
- 分析师分类层 `{asset_id: {score_class, attack_surface, trust_zone, reachable, depends_on, decoy...}}`；recon 不含计分分类与可达性，由该层补齐。
- 计分模型（§2.2/§2.3）：AI向量机/独立机 15、传统向量机 10、域控 5（单次）、链式入口低杠杆、诱饵机 0。
- 可选：RoE 规则、上一版威胁模型（prior）、增量情报（new_intel）、既有诱饵判定线索。

## 4. 输出与产物

- 高价值资产清单：按计分降序，明确 AI向量机/独立机排名与攻击面归属（D1–D11）。
- 信任边界 + 最短攻击路径图：每条路径含起止资产、必经阶段、预计耗时、依赖前置子技能、状态（可达/待补）；A2A 目标另含协调模式、三层信任边界与四类攻击向量。
- 诱饵判定清单：每台含三维度依据、放弃理由、时间戳，时间盒 ≤30min。
- 优先级攻击图：根=最高杠杆资产、边=最短路径、诱饵已排除，输出 §4.5 编排顺序（AI向量机/独立机→传统链→域控 `proof.txt` 单次提交）。
- Ch10 增量节（有输入时）：假设登记册、信任边界五要素、升级路径 Go/No-Go、决策矩阵、皇冠珠宝、ATLAS 映射、六段攻击情报简报。
- 产物统一为 markdown 结构化片段，与 `report-exam`、`verify-evidence`、`decoy-detect` 可衔接。

## 5. 行为约束

- 四节推进次序固定：资产计分排序→信任边界与最短路径→诱饵机时间盒→优先级攻击图；任一关键结论缺失即未过质量门。
- 计分杠杆优先：AI向量机=独立机(15)>传统向量机(10)>域控/链式入口(5)>诱饵机(0)。
- 诱饵单台判定 ≤30min，超时记「判定不确定」并主动放弃，不在 0 分主机空耗。
- 不虚构：信号不足记「不可判定」；依赖未就绪标「待补」；A2A 无线索记 `UNDETERMINED`。
- Ch9 身份链资产 ID 稳定（`iam-<role>`/`k8s-sa-<name>`），复用既有 `boundaries.shortest_paths`，不改诱饵判定与优先级图语义；纯分析、零网络。
- 结论可被技术读者 copy/paste 逐步复现；排序与路径附来源锚点（§2.2/§2.3、分类依据、时间盒时间戳）。
- 术语符合 `GLOSSARY.md`：用「威胁模型」「信任边界」「最短攻击路径」「优先级攻击图」「诱饵机」「AI向量机」「独立机」，禁用废弃同义词。

## 6. 失败与豁免

- 目标无可用高价值 AI 面：记录判定依据后改走传统向量机链（`foothold-traditional`），不阻塞整体规划。
- 无 A2A Agent Card 或编排端点线索：协调模式记 `UNDETERMINED`，不虚构拓扑或信任关系。
- 诱饵判定信息不足：严格按时间盒 ≤30min 结束并主动放弃，记录理由。
- 最短路径依赖的前置子技能未就绪：显式标注该路径为「待补」，不虚构可达性。
- 技能仅做规划产出，不含任何实际攻击利用；所有结论待对应攻击子技能实战验证。

## 7. 不在范围

- 不执行任何实际攻击、漏洞利用或横向移动。
- 不做网络探测/扫描，不读实时拓扑，不执行 assume-role 或 token 提取。
- 不引入 PyRIT 或其它攻击框架对象图（威胁建模是分析活动，框架是被建模对象）。
- 不自动指纹推断计分分类：分类由分析师标注，工具不臆测。
- 不修改 `recon-ai` 产出与本技能之外的既有文件。

## 1. Problem Statement

24h 节奏（§5.4）下批量枚举、证据收集、校验高频重复。共享工具齐备但缺编排层：逐步敲命令、自维步骤标识、自行汇总，导致节奏拖慢、漏跑致证据片段无法按 `<prefix>-01..0N` 归档、结果散落难交全量校验（§8.2）。各攻击子技能若各写循环、各起证据收口，将形成多套判据破坏质量基线（§6）。本技能要在**不新增外部依赖、不退化 S1/S2、不含攻击逻辑**前提下收敛可脚本化动作为可复用编排层，人工判读标注手动。

## 2. Solution

「任务清单归一 → 复用既有工具串联 → 结构化汇总」三段：

- **归一**：声明式列出任务类别、目标、步骤标识、输入/输出、触发条件与「可脚本化 / 手动」分类；覆盖率分母只取可脚本化任务。
- **串联**：编排层只做「调用 + 串联 + 汇总」。证据收口仍由既有工具承担（严格模式判三件套与双通道一致性），解剖、术语、预算、覆盖率判定仍用既有校验脚本；不重写等价逻辑。
- **汇总**：产出 markdown 表格（对齐战利品管理索引习惯）与逐步骤证据片段（`<prefix>-01..0N`）；含自动化覆盖率与剩余手动清单。
- **衔接**：汇总结果可直接进入 `verify-evidence` 八项检查单；编排件可被各攻击子技能与该校验直接调用。
- **边界**：手动任务始终标注「手动」，不伪造判定；编排层不含攻击语义。

## 3. User Stories

#### 执行体 §1（任务识别）

- US-01 考生｜批量枚举多目标一次登记、按标识执行→少敲命令。
- US-02 考生｜批量证据收集一次编排多步、每步带命令与输出→边打边写。
- US-03 考生｜批量校验（双通道、三件套）一次跑完→快速自证。
- US-04 报告负责人｜区分可脚本化与人工判读、后者标手动→不强行自动化。
- US-05 考生｜产出「任务—脚本」映射草案（输入/输出/触发条件）→判断提速环节。

#### 执行体 §2（复用编排）

- US-06 考生｜证据统一由既有工具落盘→不产生第二套实现。
- US-07 考生｜每步按严格模式判三件套与双通道一致性→缺失即失败。
- US-08 考生｜解剖、术语、预算、覆盖率校验复用既有脚本→不重写等价逻辑。
- US-09 报告负责人｜产出统一为 markdown / 表格→对齐索引习惯。
- US-10 CI｜编排层只串联既有门禁脚本→ S1/S2 保持密闭。

#### 执行体 §3（自动化件）

- US-11 考生｜可复用编排件（枚举 → 证据 → 汇总）→一次跑通。
- US-12 考生｜目标与步骤标识可参数化、复用 `<prefix>-01..0N`→跨技能复用。
- US-13 攻击子技能｜直调编排件做批量证据收集→不各自造轮子。
- US-14 全量校验使用者｜汇总结果可直接被消费→免手工整理。
- US-15 评审者｜每件注明复用声明或新增 seam 理由→判定偏离。

#### 执行体 §4（CI / verify 衔接）

- US-16 CI｜自动化件不退化 S1/S2（零外部依赖）→本地与 CI 一致。
- US-17 考生｜证据收集后直接进入八项检查单→闭环。
- US-18 报告负责人｜给出自动化覆盖率与剩余手动清单→说明提速边界。
- US-19 考生｜手动任务不计入覆盖率分母→指标不虚高。

#### 质量门

- US-20 评审者｜映射明确可脚本化/手动分类→核验无强行自动化。
- US-21 评审者｜复用声明到「无重复实现」、新增 seam 记理由与影响→可追溯。
- US-22 子技能与全量校验｜编排件有明确可调用入口→直接集成。
- US-23 报告负责人｜证据片段与战利品管理、全量校验可衔接→复用索引习惯。

#### 校验标准

- US-24 技术读者｜copy/paste 逐步复现、调用与串联顺序有据→可复核。
- US-25 报告负责人｜产出与全量校验、报告证据消费直接兼容→免二次转换。
- US-26 评审者｜全文用规范术语、无废弃术语→检查器放行。

#### 失败与豁免

- US-27 考生｜无法脚本化任务标手动并给原因→不出现假绿。
- US-28 评审者｜新增 seam 必记理由与影响→不静默破坏 CI 门禁。
- US-29 考生｜编排件不承载攻击逻辑→职责边界清晰。
- US-30 CI｜输入非法或步骤标识冲突报用法错误→失败可诊断。

## 4. Implementation Decisions

- **接缝（seam）**：**1 处**，已与用户核对确认（2026-11-15，选定「1 处（推荐）」）。
  - S-1 统一编排入口：最外层，CLI 与库调用共用；任务清单由此进入，外部命令执行器可注入，使测试替身替换真实脚本调用。
  - 新增理由：质量门要求可被直调、测试需注入替身；严格零新增将缺失库调用形态。1 处为「零新增 seam 优先」下最小折中。
  - 既有接缝复用：证据收集工具的步骤/严格模式命令行边界与校验脚本退出码边界均为现成接缝，不另立判据。
- **单一事实源**：三件套、双通道、五要素、术语与预算判据复用既有工具结论。
- **零第三方依赖**：仅标准库，不改动既有门禁脚本行为。
- **参数化契约**：目标与步骤标识参数化，命名空间沿用 `<prefix>-01..0N`；非法输入或冲突以用法错误退出。
- **只读编排**：只调用与汇总，不改证据本体、不回写登记簿、不改写报告。
- **指标口径**：覆盖率分母固定为可脚本化任务全集，手动任务单列；阶段 3 布尔化。
- **退出码契约**：全通过 / 门禁失败 / 用法错误三值固定。
- **职责边界**：不含攻击逻辑、不调用 PyRIT 对象图。

## 5. Testing Decisions

- 只测外部行为：断言「任务清单 → 调用序列 / 汇总结果 / 退出码」，不断言内部细节。
- 参考测试：证据收集工具自测（临时夹具断言三件套、严格模式）、校验器自测（合规/不合规夹具）；标准库 `unittest`。
- 夹具：临时目录造任务清单与输出路径；外部命令经 S-1 注入替身，不依赖真实考试环境；另留真实脚本串联用例。
- 覆盖：全绿、步骤缺失、严格模式失败、手动标注、标识冲突、退出码三值、替身替换。
- 覆盖率目标：业务代码 ≥80%（CI S2）。

## 6. Out of Scope

- 不含攻击逻辑、不做 PyRIT 调用与对象图装配。
- 不自动化人工判读（flag 值级真伪、访问证明截图同屏判读）。
- 不重写证据收集、解剖、术语、预算、覆盖率校验实现。
- 不生成报告 PDF / 归档包，不改写报告与登记簿。
- 不新增外部依赖，不修改 CI 门禁阶段定义。
- 不替代 CI：编排件是被 CI 调用的对象。

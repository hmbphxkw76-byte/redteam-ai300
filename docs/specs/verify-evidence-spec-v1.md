## 1. Problem Statement

提交为**终态、不可修改**且有 24h 窗口（§7.3）；失分条款（§2.4.2）的触发条件极廉价：flag 未同时出现在面板**与**报告（或文档缺失）即失分。100 分制、及格 75 分，一处疏漏可把已到手的 15 分归零。

现状缺口三类：① 八项检查单中「三件套」「双通道」「访问证明同屏」「24h」跨多工具，人眼过一遍必漏；② 三件套判据在登记簿与报告侧各有一份，会漂移，造成本地绿灯而 CI 红灯；③ 无统一机读结果，CI 无法自动化阻断。

本技能要解决：在 `report-exam` 之后、提交之前，用**一次可重复的机器判定**把「因文档问题失分」压到零，并给出精确到目标/步骤/检查项的缺失清单。

## 2. Solution

以「输入归一 → 逐项判定 → 机读输出」三段结构承载八项检查单 + 域控单次约束：

- **输入归一**：把三类既有产物（报告正文与附录、证据片段集合；登记簿双通道单元格；产物路径与时间戳）归并为单一输入模型。
- **逐项判定**：八项检查单各一独立判定，输出「通过/阻断 + 缺失项」；域控单次约束为第九项。
- **分级处置**：违反「必须」→ 阻断；未取分目标缺失 → 记录不阻断（属预期）；环境受限未生成产物 → 记核实闸，**永不**标记可提交。
- **机读输出**：固定 schema 的 JSON（checks 布尔表、blocking、missing、pending、passed、submission_ready），退出码 0/1/2，供 `report-exam` 与 CI 消费；另出人读摘要，缺失项定位到目标/步骤/检查项。

未过门禁不得提交；判定客观可复现，豁免按 §8.3 显式声明。

## 3. User Stories（长清单）

#### 输入与衔接

- US-01 作为考生，我希望校验器直接吃 `report-exam` 的产出一份输入，不必手拼中间格式，以便提交前 5 分钟内跑完。
- US-02 作为考生，我希望直接读登记簿双通道单元格（面板值 / 截图路径），以便「登记即校验」。
- US-03 作为考生，我希望读一批 `collect_evidence` 片段文件，自动判定每步三件套。
- US-04 作为报告负责人，我希望输入缺失或格式非法时报「用法错误」而非静默通过。

#### 八项检查单（vrf-01…vrf-08）

- US-05 检查单 1：核对全部已纳管技能的五要素与元信息（§4.2/§4.4），并以仓库技能校验器的结论为准，不在本技能内另立判据。
- US-06 检查单 2：核对报告的目标计分清单覆盖 8 个计分目标、分值合计 100，且分值与评分杠杆一致（AI 向量 15 / 传统 10 / 独立 15 / 域控 5）。
- US-07 检查单 3：对每个**已取分**步骤核对「确切命令 + 关键输出 + 截图」三件套齐全；未取分步骤的缺失记为缺失项，不阻断。
- US-08 检查单 4：对每个 flag 比对控制面板提交值与报告值，逐字一致；有报告值而无面板值即阻断。
- US-09 检查单 4 续：flag 取证须有「访问证明」——截图中 `whoami`/`id` 与 flag 内容同屏；无访问证明即阻断。
- US-10 检查单 5：全程 AI 交互（prompt、模型、输出、采纳决策）逐字出现在附录中；片段带 AI 日志而附录缺失即阻断。
- US-11 检查单 6：报告四章结构与关键锚点齐全（Introduction/Objective/Requirements、Executive Summary 含 High-Level Attack Path、Attack Walkthrough、Appendix），技术读者可 copy/paste 复现。
- US-12 检查单 7：产物存在、命名合规（`OSAI-OS-<OSID>-Exam-Report.pdf` / `.7z`）、归档无密码、≤100MB。
- US-13 检查单 7 续：提交时刻距考试结束不超过 24h；超窗即阻断（S3：自动不及格）。
- US-14 检查单 8：叙述正文不含 `GLOSSARY.md` 标注的废弃术语；证据区间内逐字原文不受术语改写约束。

#### 域控与整体结论

- US-15 域控 `proof.txt` 提交记录不超过 1 条；多于 1 条即阻断。
- US-16 作为考生，我希望一次运行得到「通过 / 阻断 + 缺失项清单」，并能据此判断能否提交。
- US-17 作为 CI，我希望消费固定 schema 的机读结果，对 `passed=false` 直接失败。
- US-18 作为考生，我希望 dry-run（未生成产物）时结果**绝不**标记为可提交，只记核实闸。

#### 质量门与豁免

- US-19 任一阻断项不符即不得进入提交动作，且不得以「后续补做」替代。
- US-20 未取分目标的证据缺失属预期，报告须如实记「未达成」，校验器不得将其计为阻断。
- US-21 双通道不一致时必须回溯补正后重校，不妥协放行；校验器只判定、不修改产物。
- US-22 24h 窗口临近而仅剩非阻断瑕疵时，允许阻断项清零后提交，剩余瑕疵记录在案。

## 4. Implementation Decisions

- **接缝（seam）**：4 处，均已与用户核对并确认（2026-11-15，用户选定「4 处全保留」）：
  - S-1 输入接缝：三类输入 → 统一输入模型，位于最外层，CLI 与库调用共用。
  - S-2 判据接缝：九项判定各自独立、纯函数、可单独回归。
  - S-3 外部工具接缝：技能校验器、术语检查器、文件系统与时钟三项外部依赖可注入。
  - S-4 输出接缝：机读 JSON（schema 版本化）+ 人读摘要。
- **判据单一事实源**：三件套与双通道判定复用登记簿既有实现，不另立更宽判据。
- **失败分级语义**：`blocking`（违反必须）/ `missing`（预期缺失）/ `pending`（核实闸）三类互斥，禁止混用。
- **退出码契约**：0/1/2 三值固定，脚本化调用不得依赖文本输出。
- **零第三方依赖**：仅标准库，可离线运行。
- **不修改产物**：只读判定，不写报告、不改登记簿。
- **范围外判定**：截图 OCR 值级比对不做，以同屏文字断言 + 人工判据替代。

## 5. Testing Decisions

- 只测外部行为：以「输入 → 判定结果 / 退出码」为断言单位，不断言内部函数调用顺序或私有结构。
- 夹具以临时目录构造「合规包 / 各类不合规包」，覆盖：全绿、缺面板 flag、重复 proof、缺章节、超 24h、超 100MB、命名错、附录缺 AI 日志、废弃术语（正文 vs 证据区间）。
- 时间与文件系统通过注入替身控制，不依赖真实时钟与真实大文件。
- 复用既有参考测试组织方式，保持标准库 `unittest`。
- 覆盖率目标：业务代码行覆盖率 ≥80%（CI S2）。

## 6. Out of Scope

- 不改写报告、不修正双通道不一致（只判定）。
- 不做截图 OCR / 图像理解。
- 不生成 PDF / `.7z`（属 `report-exam`）。
- 不替代 `loot-manage` 的登记簿质量门。
- 不做考试窗口自动计时（只判「距考试结束时长」输入值）。
- 不做 PyRIT 攻击调用（本技能 S1-only，无对象图）。

## 7. Further Notes

- 与 `report-exam`：本技能是其提交前置（§7.3），组装侧已委托同一校验器。
- 与 `loot-manage`：登记簿是双通道与三件套上游；本技能只消费、不回写。
- 与 CI：机读结果可直接作为 job 断言目标；dry-run 语义保证「未生成产物不假绿」。
- 核实闸 VG-1（章节名是否官方用语）/ VG-2（访问证明是否必须含 `whoami`）见调研文档；VG-1 不成立则改按目标键集判定。

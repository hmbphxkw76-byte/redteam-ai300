# 阶段 1 · research（调研）— 独立提示词

> 同步源：`docs/standards/cross-ide-mainline-workflow.md` §4.1（唯一事实源；本文件是 IDE 部署层副本，修改须两处同步，见 README「同步规则」）。

| 字段 | 内容 |
|---|---|
| 目标 | 用一手来源锁定实现依赖的事实（API 名称、版本、行为边界），消除规格阶段的猜测 |
| 输入 | 能力声明文档 `{CAPABILITY_DOC}`（行为唯一来源）；官方仓库 / 官方文档 / 源码；既有调研索引 |
| 输出 | `docs/research/{TOPIC}.md`：逐条结论附来源 URL 与版本，含「已核实 / 待核实 / 已排除」三类清单 |
| 触发条件 | 主线整体触发时自动首跑；单阶段触发：说「调研 {TOPIC}」或粘贴下方提示词 |
| 上游衔接 | 只消费能力声明文档，只读、不改写 |
| 下游衔接 | 产出被阶段 2（撰写 v1 的事实底座）与阶段 3（待核实项取证）消费 |
| G0 门禁 | B7、B8（B1–B8 通用基线定义见 cross-ide doc §3） |

## 提示词正文（整段复制即生效）

```text
你是资深软件开发工程师，正在执行 11 阶段主线工作流的阶段 1 research。
上游输入：能力声明文档 {CAPABILITY_DOC}（行为唯一来源，只读不改写）。若缺失，先向用户索取，不得凭空假设。
任务：针对该文档声明的全部能力，用一手来源（官方仓库 / 官方文档 / 源码）核实实现依赖的事实：
API 名称、版本、行为边界。逐项回溯到拥有该事实的源，记录版本破坏性变更与禁用/已废弃名称，
标出实现前必须取证的核实闸。
产出 docs/research/{TOPIC}.md：每条结论附来源 URL 与版本，含「已核实 / 待核实 / 已排除」三类清单。
完成后按 G0 收尾（重点 B7、B8）：列出不符合项与修正要求；结论 PASS 才进入阶段 2，BLOCKED 则停留本阶段重跑检查。
```

## G0 收尾自检

- [ ] 每条结论可定位到官方源，且版本号明确
- [ ] 每条能力路径有对应对象映射
- [ ] 待核实项逐条命名并给出取证方式
- [ ] 产物已落盘 `docs/research/{TOPIC}.md`

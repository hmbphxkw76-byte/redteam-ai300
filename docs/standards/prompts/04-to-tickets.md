# 阶段 4 · to-tickets（工单拆解）— 独立提示词

> 同步源：`docs/standards/cross-ide-mainline-workflow.md` §4.4。修改须两处同步（见 README「同步规则」）。

| 字段 | 内容 |
|---|---|
| 目标 | 把 v2 拆成可独立交付、可并行判定的垂直切片（tracer bullet），显式声明依赖 |
| 输入 | 规格 v2（issue {ISSUE}）；issue tracker 的 sub-issue / blocking 约定；既有工单编号 |
| 输出 | 父工单 + 每能力路径一张子工单 + 证据契约工单；每张含目标、验收条件、阻塞边、验证命令；覆盖矩阵 |
| 触发条件 | 主线整体触发时自动第四跑；单阶段触发：说「拆工单」或粘贴下方提示词 |
| 上游衔接 | 消费 v2 定稿；每条 v2 验收条件必须被至少一张工单覆盖（映射表是衔接件） |
| 下游衔接 | 工单是阶段 5 triage 的对象、阶段 8 实现的工作单元 |
| G0 门禁 | B2、B8 |

## 提示词正文（整段复制即生效）

```text
你是资深软件开发工程师，正在执行 11 阶段主线工作流的阶段 4 to-tickets。
上游输入：规格 v2 定稿（issue {ISSUE}）。若 v2 不存在，回退阶段 3。
任务：把 v2 拆成可独立交付、可并行判定的垂直切片（tracer bullet），每片保留一条端到端可运行链路。
产出：父工单 + 每能力路径一张子工单 + 证据契约工单；用 blocked-by（或回退文本 Blocked by: #n）声明依赖。
每张工单必须含：目标、验收条件（引用 v2 条目编号）、阻塞边、验证命令。
校验：覆盖矩阵无空格（每条 v2 验收条件至少被一张工单覆盖）、无环形依赖、标题术语与 GLOSSARY 一致、每张工单可单独验收。
完成后按 G0 收尾（B2/B8）：列不符合项与修正要求；结论 PASS 才进入阶段 5。
```

## G0 收尾自检

- [ ] 覆盖矩阵：v2 每条验收条件至少被一张工单覆盖
- [ ] 每张工单可单独验收，含目标/验收条件/阻塞边/验证命令
- [ ] 依赖边可查询，无环
- [ ] 标题术语与 GLOSSARY 一致

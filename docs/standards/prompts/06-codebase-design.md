# 阶段 6 · codebase-design（模块与接口设计）— 独立提示词

> 同步源：`docs/standards/cross-ide-mainline-workflow.md` §4.6。修改须两处同步（见 README「同步规则」）。

| 字段 | 内容 |
|---|---|
| 目标 | 确定深层模块边界与 seam 位置，使实现可测试、可注入、对 agent 可导航 |
| 输入 | 规格 v2（issue {ISSUE}）；阶段 4 工单；现有目录与模块边界；阶段 2 已确认的 seam 提案 |
| 输出 | 设计记录：模块职责、公开接口（职责/输入/输出/错误行为）、依赖方向、seam 清单、注入点、对象图构造位置 |
| 触发条件 | 主线整体触发时自动第六跑；单阶段触发：说「codebase-design 设计」或粘贴下方提示词 |
| 上游衔接 | 消费 v2 与阶段 2 已核对的 seam 提案（设计结论必须与其一致） |
| 下游衔接 | 设计记录是阶段 7 术语来源之一、阶段 8 实现的结构约束、阶段 9 测试替身的挂载依据 |
| G0 门禁 | B2、B7、B8 |

## 提示词正文（整段复制即生效）

```text
你是资深软件开发工程师，正在执行 11 阶段主线工作流的阶段 6 codebase-design。
上游输入：规格 v2（issue {ISSUE}）、阶段 4 工单、现有代码结构与边界、阶段 2 已确认的 seam 提案。
若 v2 或 seam 提案缺失，回退对应上游阶段。
任务：确定深层模块边界与 seam 位置。原则：
复用既有 seam；新 seam 压到最少并置于最高层；公开入口最小、可注入依赖显式；
依赖方向单向；外部依赖（框架/外部服务）延迟导入并提供测试假后端策略；
对象图统一采用当前版本 API（禁用已废弃对象，以阶段 1 调研文档为准）。
产出设计记录：模块职责、每个公开接口的职责/输入/输出/错误行为、依赖方向、seam 清单、注入点、对象图构造位置。
与既有 ADR 冲突须显式标注，不静默覆盖。
完成后按 G0 收尾（B2/B7/B8）：列不符合项与修正要求；结论 PASS 才进入阶段 7。
设计决定后续测试成本：接口要少、实现要深。
```

## G0 收尾自检

- [ ] seam 数量与位置明确，且与阶段 2 结论一致
- [ ] 每个公开接口有职责/输入/输出/错误行为描述
- [ ] 依赖方向单向；测试替身可替换外部依赖
- [ ] 与 ADR 冲突已显式标注

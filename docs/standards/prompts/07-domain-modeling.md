# 阶段 7 · domain-modeling（领域术语建模）— 独立提示词

> 同步源：`docs/standards/cross-ide-mainline-workflow.md` §4.7。修改须两处同步（见 README「同步规则」）。

| 字段 | 内容 |
|---|---|
| 目标 | 把实现引入的新概念纳入唯一术语基准，消除代码/规格/报告之间的语义漂移 |
| 输入 | 规格 v2、阶段 6 设计记录、`GLOSSARY.md`、ADR 目录、实现层词汇清单 |
| 输出 | `GLOSSARY.md` 增补（定义、禁用同义词、来源）；必要时新增 ADR；术语映射表（能力概念 ↔ 实现对象 ↔ 代码标识符） |
| 触发条件 | 主线整体触发时自动第七跑；单阶段触发：说「domain-modeling 术语」或粘贴下方提示词 |
| 上游衔接 | 消费 v2 与设计记录中的全部新概念（映射表须全覆盖） |
| 下游衔接 | GLOSSARY 是阶段 8 命名、阶段 9/10 审查与后续会话的术语唯一基准 |
| G0 门禁 | B1、B2、B8 |

## 提示词正文（整段复制即生效）

```text
你是资深软件开发工程师，正在执行 11 阶段主线工作流的阶段 7 domain-modeling。
上游输入：规格 v2（issue {ISSUE}）、阶段 6 设计记录、现有 GLOSSARY.md 与 ADR 目录。
任务：把本次实现引入的新概念纳入唯一术语基准。步骤：
1) 枚举规格与设计中的全部新术语；
2) 与 GLOSSARY 既有条目比对归一（同义合并，禁用同义词显式标注）；
3) 为每个术语写定义、来源（指向 v2/设计记录/官方文档）；
4) 涉及架构决策且影响后续维护的，新增 ADR（编号连续、冲突显式标注）；
5) 产出术语映射表：能力概念 ↔ 实现对象 ↔ 代码标识符。
若项目配有术语检查器（如 check_glossary），运行须通过。
完成后按 G0 收尾（B1/B2/B8）：列不符合项与修正要求；结论 PASS 才进入阶段 8。
```

## G0 收尾自检

- [ ] 映射表覆盖规格与设计中的全部新概念
- [ ] `GLOSSARY.md` 每个新条目含定义与来源
- [ ] 术语检查器通过（若存在）
- [ ] ADR 编号连续、冲突显式标注

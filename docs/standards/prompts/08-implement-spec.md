# 阶段 8 · implement-spec（按规格实现）— 独立提示词

> 同步源：`docs/standards/cross-ide-mainline-workflow.md` §4.8。修改须两处同步（见 README「同步规则」）。

| 字段 | 内容 |
|---|---|
| 目标 | 按 v2 + 工单产出接口完整、可编译、可验证的最小实现切片，保持与能力声明一致 |
| 输入 | 规格 v2（issue {ISSUE}）；`ready-for-agent` 工单与 brief；阶段 6 设计记录；`GLOSSARY.md`；依赖权威索引 |
| 输出 | 实现代码（模块、对象图构造、公开入口）、必要配置与依赖声明、每步证据三件套（命令 + 输出 + artifact）、变更清单 |
| 触发条件 | 主线整体触发时自动第八跑；单阶段触发：说「implement-spec 实现」或粘贴下方提示词 |
| 上游衔接 | 消费 5（工单+brief）、6（结构约束）、7（命名基准）三类输入，缺任一回退对应阶段 |
| 下游衔接 | 实现切片是阶段 9 tdd 的被测对象；规格偏差由阶段 9 暴露并退回本阶段 |
| G0 门禁 | B1、B2、B3、B4、B5、B7、B8 全项 |

## 提示词正文（整段复制即生效）

```text
你是资深软件开发工程师，正在执行 11 阶段主线工作流的阶段 8 implement-spec。
上游输入：规格 v2（issue {ISSUE}）、ready-for-agent 工单与 brief、阶段 6 设计记录、GLOSSARY.md。
若任一缺失，回退对应上游阶段，不得在无约束状态下开工。
任务：按工单逐片产出接口完整、可编译、可验证的最小实现切片。
规则：外部依赖一律走阶段 6 定义的注入点；对象图遵循设计记录；
每步产出证据三件套（命令 + 输出 + artifact 路径），确保技术读者可 copy/paste 复现；
能力声明文档始终是行为唯一来源；无硬编码凭据；变更清单与工单一一对应。
本阶段只交付最小切片，完整测试收敛在阶段 9。
完成后按 G0 收尾（B1/B2/B3/B4/B5/B7/B8 全项；门禁记录须含每条命令输出摘要，运行门禁套件 {GATE_CMD}）：
列不符合项与修正要求；结论 PASS 才进入阶段 9。
```

## G0 收尾自检

- [ ] 每条 v2 验收条件有对应实现位置（映射可查）
- [ ] 可编译/可构建；对象图符合设计
- [ ] 每步证据三件套齐全且可复现
- [ ] 无硬编码凭据；变更清单与工单一一对应

# 阶段 9 · tdd（测试驱动开发）— 独立提示词

> 同步源：`docs/standards/cross-ide-mainline-workflow.md` §4.9。修改须两处同步（见 README「同步规则」）。

| 字段 | 内容 |
|---|---|
| 目标 | 以 v2 为判据补齐红—绿—重构循环，用测试锁定外部行为并收敛实现 |
| 输入 | v2 布尔验收条件（issue {ISSUE}）；阶段 8 实现切片；既有测试夹具；覆盖率要求 `{COVERAGE}` |
| 输出 | 新增/修订测试用例、证据契约夹具、红→绿→重构三轮记录、覆盖率数据 |
| 触发条件 | 主线整体触发时自动第九跑；单阶段触发：说「tdd 测试」或粘贴下方提示词 |
| 上游衔接 | 消费阶段 8 实现与 v2 验收条件（每条验收条件须有对应测试） |
| 下游衔接 | 测试全绿与覆盖率达标是阶段 10 审查的前置；测试暴露规格偏差时退回阶段 8 并重跑其门禁 |
| G0 门禁 | B3、B4、B6、B8 全项 |

## 提示词正文（整段复制即生效）

```text
你是资深软件开发工程师，正在执行 11 阶段主线工作流的阶段 9 tdd。
上游输入：v2 验收条件（issue {ISSUE}）与阶段 8 实现切片。若实现缺失，回退阶段 8。
任务：以 v2 为判据补齐红—绿—重构循环：
为每条验收条件写一个失败用例（红，失败输出须留痕）→ 最小改动使其通过（绿）→ 重构并复跑（重构）→ 补证据契约夹具。
规则：只测外部行为，不断言实现细节；测试替身挂载在阶段 6 定义的 seam 上；
运行全量测试与覆盖率，业务代码覆盖率 ≥ {COVERAGE}；本地与 CI 判定须一致。
测试暴露规格偏差时：退回阶段 8 修正实现并重跑其门禁；若偏差源于 v2 本身，按上游复核路径回退阶段 3，不擅自改规格。
完成后按 G0 收尾（B3/B4/B6/B8，附全量测试输出与覆盖率数字）：列不符合项与修正要求；结论 PASS 才进入阶段 10。
```

## G0 收尾自检

- [ ] 每条 v2 验收条件有对应测试
- [ ] 红阶段有实际失败输出留痕；全量测试通过
- [ ] 覆盖率 ≥ `{COVERAGE}`（附数字）
- [ ] 只测外部行为；本地与 CI 判定一致

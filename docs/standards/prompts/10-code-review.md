# 阶段 10 · code-review（双轴代码审查）— 独立提示词

> 同步源：`docs/standards/cross-ide-mainline-workflow.md` §4.10。修改须两处同步（见 README「同步规则」）。

| 字段 | 内容 |
|---|---|
| 目标 | 相对固定基线，独立审查 Standards（编码规范）与 Spec（规格忠实度）两条轴，输出并列结论 |
| 输入 | 基线 `{BASE_REF}` 之后的 diff；规格 v2 与工单；编码规范、`GLOSSARY.md`、项目约定 |
| 输出 | 双轴并列报告（每轴发现数、最严重项、逐条分类：硬违规 / 判断项）、修复清单、复跑结果 |
| 触发条件 | 主线整体触发时自动第十跑；单阶段触发：说「code-review 审查」或粘贴下方提示词 |
| 上游衔接 | 消费阶段 9 全绿结论之后的全部变更；Spec 轴以 v2 为唯一判据 |
| 下游衔接 | 双轴结论 + 硬违规清零 + 门禁全绿是阶段 11 推送的前置条件 |
| G0 门禁 | B1–B8 全项 |

## 提示词正文（整段复制即生效）

```text
你是资深软件开发工程师，正在执行 11 阶段主线工作流的阶段 10 code-review。
上游输入：固定基线 {BASE_REF} 之后的全部 diff、规格 v2（issue {ISSUE}）与工单、编码规范与 GLOSSARY.md。
任务：并行、独立地审查两条轴，不合并、不重排：
轴一 Standards——代码是否遵循本仓库文档化的编码规范与术语；
轴二 Spec——代码是否忠实于 v2 验收条件与工单意图（规格覆盖矩阵逐条对照）。
每条发现带文件位置并分类：硬违规 / 判断项。
处置：硬违规先修复并复跑门禁套件 {GATE_CMD}；判断项记录为改进项，不阻塞。
要求：两轴报告并列且各自结论完整；硬违规数量为 0；规格覆盖矩阵无遗漏；门禁套件全绿。
完成后按 G0 收尾（B1–B8 全项）：列不符合项与修正要求；结论 PASS 才进入阶段 11。
```

## G0 收尾自检

- [ ] 两轴报告并列、各自结论完整（发现数 + 最严重项）
- [ ] 每条发现带文件位置与硬违规/判断项分类
- [ ] 硬违规为 0；规格覆盖矩阵无遗漏
- [ ] 门禁套件复跑全绿

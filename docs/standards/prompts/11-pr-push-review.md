# 阶段 11 · pr-push-review（PR 与推送前评审，复合阶段）— 独立提示词

> 同步源：`docs/standards/cross-ide-mainline-workflow.md` §4.11。修改须两处同步（见 README「同步规则」）。
> 复合阶段，内部次序固定：pre-push-review → pr → 推送与 PR 创建。

| 字段 | 内容 |
|---|---|
| 目标 | 完成推送前语义级双轴评审、PR 正文、双通道推送与 PR 创建，衔接 CI 门禁 |
| 输入 | 阶段 10 全绿结论；工作树与分支 commits；远端基线 `{BASE_REF}`；规格 v2；PR 模板；双通道推送约定 `{PRIMARY_CHANNEL}` / `{BACKUP_CHANNEL}` |
| 输出 | pre-push-review 双轴报告与门禁结果、PR 正文（四节）、PR 链接与编号、CI 状态、推送结果记录、`Closes #x` |
| 触发条件 | 主线整体触发时自动第十一跑（终点）；单阶段触发：说「pr-push-review 发布」或粘贴下方提示词 |
| 上游衔接 | 消费阶段 10 全绿结论；未全绿不得进入本阶段 |
| 下游衔接 | 终点阶段：PR 合并 + CI 全绿即主线闭环；B1–B8 全量汇总在本阶段出具一次 |
| G0 门禁 | B1–B8 全项（全量汇总一次） |

## 提示词正文（整段复制即生效）

```text
你是资深软件开发工程师，正在执行 11 阶段主线工作流的阶段 11 pr-push-review（复合阶段，内部次序固定）。
前置：阶段 10 双轴全绿。未全绿则回退阶段 10。
1) pre-push-review：取远端基线 {BASE_REF} → 语义级双轴评审（Standards / Spec，不合并）→ 分类发现
   （硬违规 / 判断项）→ 按确认批次修复 → 复跑门禁套件 {GATE_CMD}。最多 3 轮收敛。
2) pr：按模板写 PR 正文四节——Summary（最小可视化）/ Evidence（改前改后证据，引用已落盘产物路径）/
   Merge Danger（单向门/双向门与影响半径）/ 四项纳管字段。
3) 推送与 PR：Conventional Commits → 优先 {PRIMARY_CHANNEL} 推送，失败则转 {BACKUP_CHANNEL}（各试一次即停，
   不循环重试）→ 受保护分支经 PR 合并 → 确认 CI 全绿 → 记录 Closes #x。
完成后按 G0 收尾（B1–B8 全量汇总，本阶段出具一次；逐条判定语义不变）：列不符合项与修正要求。
3 轮未收敛或推送双通道均失败：输出未收敛清单并停留本阶段，等待用户决策。
```

## G0 收尾自检

- [ ] 双轴报告含每轴发现数与最严重项；门禁套件全绿
- [ ] PR 正文四节齐全（≤ 预算上限，验收条件逐条完整保留）
- [ ] 推送记录含实际通道与结果；CI 全绿；`Closes #x` 已记录
- [ ] B1–B8 全量汇总已出具一次

# decoy-detect — 诱饵机识别

exam 环境中存在 2 台**诱饵机（0 分）**，投入时间攻击会直接拉低通过率。本技能覆盖 D2（诱饵机识别），在 **≤30min 时间盒（§5.3）**内基于**行为 / 漏洞缺失 / 无价值**三维度特征识别诱饵机并主动放弃，产出的判定清单与 `threat-model` 形成闭环复核，避免 0 分主机空耗。

## 执行体

按「三维度特征提取 → 时间盒判定 → 诱饵判定清单 → 与 threat-model 衔接」四节推进；严格守时，超时即记录「不确定」并放弃。

### 1. 三维度特征提取

对每台待判定主机提取三类信号，任何一类命中即记为疑似诱饵：

1. **行为特征**：无 AI 基础设施面（无模型服务器/向量库/推理网关）、无可驱动 AI 利用的入口。
2. **漏洞缺失**：无高价值服务、无可达入口、无可利用配置错误（枚举后无有效攻击面）。
3. **无价值特征**：枚举反馈异常「过干净」（无任何banner/服务）、信息缺失到无法定位资产、与资产清单描述严重不符。

### 2. ≤30min 时间盒判定

1. 单台判定**硬性时间盒 ≤30min**；从开始枚举到得出结论不得超过该时长。
2. 超时或信息不足即记录「判定不确定」，按 §5.3 主动放弃该主机，写入放弃理由，不在 0 分主机空耗。
3. 命中三维度中≥2 类即判定为诱饵；仅 1 类命中需结合威胁模型交叉验证，避免误杀真高价值目标。

### 3. 诱饵判定清单

1. 对判定为诱饵（含不确定放弃）的每台主机，产出结构化清单条目：**主机标识 + 命中维度 + 具体依据 + 放弃理由 + 时间戳**。
2. 明确标注「诱饵」或「不确定-已放弃」两种结论，不混淆。
3. 清单以 markdown 落盘，与 `loot-manage` 索引习惯一致，可被 `report-exam` 直接引用。

### 4. 与 threat-model 衔接

1. 若本技能独立运行，结论回灌 `threat-model` 的优先级攻击图，将其从攻击目标中排除。
2. 若收到 `threat-model` 的诱饵初筛，进行**复核**：一致则确认，冲突则以多维度交叉验证为准并更新结论。
3. 最终诱饵集合（应≈2 台）须与考试规模预期对齐；明显偏离时复核判定逻辑。

## 质量门

以下结论**必须**全部产出，缺失任一即判定未过门禁：

- **诱饵判定清单**（每台含：主机标识 / 命中维度 / 具体依据 / 放弃理由 / 时间戳）。
- **时间盒合规**：每台判定耗时 ≤30min，超时有显式「不确定-已放弃」记录。
- **维度交叉验证**：仅单维度命中时须经威胁模型或人工复核，未误杀真目标。
- 落盘片段与 `threat-model` / `report-exam` 可衔接（复用 `loot-manage` 索引习惯）。

## 校验标准

- 判定过程可被技术读者 **copy/paste 逐步复现**（§6.1），三维度依据与放弃理由有据可查。
- 产出与 `threat-model` 编排排除、`report-exam` 的诱饵记录直接兼容，可无损复用。
- 术语符合 `GLOSSARY.md`（统一用「诱饵机」，禁用 `_Avoid_` 废弃术语，见 GLOSSARY.md）。

## 失败与豁免

- 若判定不确定（信息不足），严格按 §5.3 时间盒 ≤30min 结束并主动放弃，记录理由，不在 0 分主机空耗。
- 若三维度均不命中但威胁模型标记为疑似诱饵，以多维度交叉验证为准，不武断放弃真目标。
- 若诱饵数量明显偏离预期（≠2），复核枚举完整性与判定逻辑，不强行凑数。
- 本技能仅做识别与判定，**不含任何攻击利用**，所有结论须结合实战枚举验证。

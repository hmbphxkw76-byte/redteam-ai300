# loot-manage — 战利品与凭证管理

即时登记与沉淀红队全程产出的全部战利品（凭据、会话、flag、攻击路径），形成单一事实源登记簿 `loot/registry.md`，供报告无损回溯（§6.1 可复现性）与提交前校验（§6.2 双通道）消费。对齐跨域能力域 D1（红队生命周期资产管理）与 D10（威胁建模的攻击路径沉淀），计分单元为通用（效率杠杆：横向复用凭据、避免重复劳动与证据散失）。依据 §5.2：**禁止**将战利品散落于对话上下文。

## 执行体

登记动作贯穿 §4.5 流水线全程——每次取得即登记（一行一条），而非事后补录。登记簿为单一 markdown 表，列结构固定：**编号 / 类型 / 内容 / 来源主机 / 证据片段路径 / 时间戳 / 状态 / 双通道（面板值 + 截图路径）**。每行的「证据片段路径」指向对应攻击步骤经 `tools/collect_evidence.py` 产出的片段文件，登记簿不重复存储证据本体。

### loot-01 凭据登记

1. 每取得一个口令 / 密钥 / token / API 凭据，立即追加一行：类型=`凭据`，内容为凭据本体，来源主机为取得该凭据的目标，证据片段路径指向取得步骤的片段（如 `loot/trad-06-lateral-host2.md`）。
2. 命令模板（追加登记行）：`printf '| L-<编号> | 凭据 | <USER>:<SECRET> | <来源主机> | loot/<step>.md | <ISO8601> | 有效 | — |\n' >> loot/registry.md`
3. 取得步骤本身已由来源技能完成取证；本步不重复取证，仅追加登记行并核对引用路径存在。

### loot-02 会话登记

1. 每建立一个持久会话（shell、reverse session、Web 会话 cookie、agent API 会话），追加一行：类型=`会话`，内容为接入方式（地址/端口/接入命令），状态标注存活/失效。
2. 命令模板：`printf '| L-<编号> | 会话 | <接入方式@地址:端口> | <来源主机> | loot/<step>.md | <ISO8601> | 存活 | — |\n' >> loot/registry.md`
3. 横向移动前优先查询本表复用存活会话与有效凭据，禁止对已有战利品的目标重新爆破。

### loot-03 flag 登记（双通道占位）

1. 每取得一个 flag（`trad_vector.txt` / `ai_vector.txt` / `proof.txt`），立即追加一行并**同时写入双通道占位**：面板提交值 + 截图路径（取证步骤的访问证明截图）。
2. 命令模板：`printf '| L-<编号> | flag | <FLAG_VALUE> | <目标主机> | loot/<step>.md | <ISO8601> | 已取证 | 面板=<FLAG_VALUE>；截图=<screenshot 路径> |\n' >> loot/registry.md`
3. 域控 `proof.txt` 登记时显式标注「仅可提交一次」（§2.2），防止重复提交失误。

### loot-04 攻击路径与索引沉淀

1. 每完成一段攻击路径（入口 → 主机 → 横向），在登记簿末尾「攻击路径」小节追加一行路径摘要（供 `report-exam` 的 High-Level Attack Path 复用），并核对全表索引：每行证据片段路径均存在、每个 flag 均有双通道占位。
2. 命令模板：`printf '### 攻击路径\n- 入口 <ENTRY_IP> → <HOST1>（trad-04 flag）→ <HOST2>（trad-07 flag）→ …\n' >> loot/registry.md`
3. 索引核对结果移交 `verify-evidence` 作为提交前校验输入；登记簿本体移交 `report-exam` 作为素材索引。

## 质量门

以下产出**必须**全部满足，缺失任一即判定未过门禁，不得进入下一技能：

- 登记簿 `loot/registry.md` 存在且表结构列齐全（编号/类型/内容/来源主机/证据片段路径/时间戳/状态/双通道）。
- 每行登记**可追溯**：来源主机与证据片段路径均真实存在（指向 collect_evidence.py 产物）。
- 每个 flag 均有**双通道占位**（面板提交值 + 截图路径，§6.2）。
- 无战利品散落于对话上下文（§5.2）；对话中引用战利品一律以编号（L-N）指代。
- 登记动作即时：取得后即登记，不留到阶段末补录。

## 校验标准

- 登记簿可被 `report-exam` **无损复用**：任意登记行可经证据片段路径还原完整「命令 + 输出 + 截图」，满足 §6.1 可复现性基线。
- 登记簿可被 `verify-evidence` 消费：flag 行的双通道占位支持逐项核对一致性。
- 横向复用有效：会话/凭据状态标注准确，失效项不被复用。
- 术语符合 `GLOSSARY.md`（用「战利品」「攻击链」「诱饵机」等规范词，禁用 `_Avoid_` 废弃术语）。

## 失败与豁免

- 若凭据/会话失效（目标修补、密码轮换），如实更新状态列为「失效」并保留原行（历史可追溯），不得删除记录。
- 若技能全程无战利品（目标不可达），在登记簿记录空态与原因，作为 `capstone-rehearse` 缺口清单输入；空态本身即为有效产出。
- 登记簿不含截图本体（仅路径），截图捕获实现不在本技能范围（豁免依据：Out of scope 约定）。
- 若登记行引用的证据片段缺失（文件被移动），补齐引用路径后再过质量门；禁止以对话上下文记忆替代证据。

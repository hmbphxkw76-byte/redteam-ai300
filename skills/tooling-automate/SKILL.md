# tooling-automate — 工具与编排自动化

把 24h 节奏（§5.4）下重复的**枚举 / 证据收集 / 校验**脚本化，复用既有共享工具（`tools/collect_evidence.py` 等），提速节奏。本技能覆盖跨域 D1（传统技术）/ D11（考前演练）的自动化，强调**零新增 seam 优先**（对齐 ADR-0003 复用既有无缝），不重复造轮子、不破坏既有 CI 门禁（§3 S2）。

## 执行体

按「可脚本化任务识别 → 复用共享工具编排 → 自动化件产出 → 与 CI/verify 衔接」四节推进；确需新增 seam 时须记录理由。

### 1. 可脚本化任务识别

1. 梳理各技能的高频重复动作：批量枚举（端口/服务/AI 面）、批量证据收集（`collect_evidence.py` 调用）、批量校验（flag 双通道/三件套）。
2. 区分「可脚本化」与「依赖人工判读」：前者纳入自动化，后者如实标注为手动，不强行自动化。
3. 产出「任务—脚本」映射草案，明确每类任务的输入/输出与触发条件。

### 2. 复用共享工具编排（零新增 seam 优先）

1. 以 `tools/collect_evidence.py` 为证据收口，编排层只做「调用 + 串联 + 汇总」，不另起证据实现（避免破坏 §6 质量基线）。
2. 枚举/校验脚本优先复用 `scripts/validate_skill.py`、`scripts/check_glossary.py` 与既有 `tests/` 夹具，不重写等价逻辑。
3. 编排产出统一以 markdown/表格结构化，与 `loot-manage` 索引习惯一致。

### 3. 自动化件产出

1. 产出可复用的自动化脚本/编排（如批量枚举→证据收集→汇总的 runner），参数化目标与 step 标识，复用 `<prefix>-01..0N` 命名空间。
2. 自动化件可被各攻击子技能（attack-*）与 `verify-evidence` 直接调用，作为编排流水线的提速层（§4.5）。
3. 每件自动化须注明「复用既有共享工具、零新增 seam」或「新增 seam 的理由」。

### 4. 与 CI / verify 衔接

1. 自动化件不得退化既有 CI 门禁（§3 S2）：S1 静态校验 + S2 标准库测试仍密闭、零外部依赖。
2. 与 `verify-evidence` 的校验编排衔接：自动化证据收集后可直接进入全量校验（§8.2）。
3. 记录自动化覆盖率（已脚本化任务占比）与剩余手动任务。

## 质量门

以下产出**必须**全部具备，缺失任一即判定未过门禁：

- **任务—脚本映射**：明确可脚本化/手动分类，不强行自动化依赖人工判读的任务。
- **复用声明**：自动化件明确复用 `collect_evidence.py` 等共享工具，无重复实现；确需新增 seam 须记录理由。
- **可调用性**：产出件可被 attack-* 子技能与 `verify-evidence` 调用。
- 落盘片段与 `loot-manage` / `verify-evidence` 可衔接（复用索引习惯）。

## 校验标准

- 自动化过程可被技术读者 **copy/paste 逐步复现**（§6.1），脚本调用与串联有据可查。
- 产出与 `verify-evidence` 的校验编排、`report-exam` 的证据消费直接兼容。
- 术语符合 `GLOSSARY.md`（用规范词，禁用 `_Avoid_` 废弃术语）。

## 失败与豁免

- 若某任务无法脚本化（依赖人工判读），如实标注为手动，不强行自动化。
- 若确需新增 seam，记录理由与影响，不静默破坏既有 CI 门禁（§3 S2）。
- 本技能仅做编排自动化，**不含攻击逻辑**；攻击语义由各 attack 子技能负责。
